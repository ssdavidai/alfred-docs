## What Alfred Cloud is

Alfred Cloud is the hosted version of Alfred Black. **The software is identical** — the same `ctrl-api`, the same Hermes runtime, the same four-store architecture, the same 14 surfaces — but you don't bring the VM. We provision a dedicated Hetzner Cloud VPS for you, attach an encrypted volume, stand up the Docker stack, terminate TLS, run nightly backups, and ship updates as they land in `main`.

If self-hosting Alfred Black is "I want to own the box," Alfred Cloud is "I want Alfred, not a sysadmin job."

## The shape of the offering

- **One tenant, one dedicated VPS.** Not a shared cluster, not a multi-tenant database. Your Alfred runs on a dedicated Hetzner Cloud machine — typically a `cx53` — with an encrypted volume attached. Nothing of yours touches anyone else's compute.
- **Private Tailscale mesh.** No public route into your services. The dashboard reaches your `ctrl-api` over a WireGuard mesh; the Hetzner firewall denies everything except SSH, ICMP, and the Tailscale handshake port.
- **LUKS2 full-disk encryption.** AES-256-XTS with a per-instance key generated at provision time. Even if Hetzner loses the disk, the operator can re-mount from raw bytes plus the backed-up keyfile.
- **Daily restic backups** to Hetzner Object Storage. Retention: 7 daily, 4 weekly, 6 monthly.
- **Same source tree.** Every Cloud tenant runs the same image tags that ship from `main` in [ssdavidai/alfred](https://github.com/ssdavidai/alfred). Nothing is forked. If you outgrow Cloud, you can [migrate to self-hosted](/alfred-cloud/migration) with your vault and machine state intact.

## What you get vs. what you give up

| Concern | Self-hosted Alfred Black | Alfred Cloud |
|---|---|---|
| **VM** | You bring it (any Linux box, 48 GB RAM+) | We provision a dedicated Hetzner `cx53` |
| **TLS / DNS** | You point DNS; Caddy auto-issues via Let's Encrypt | Cloudflare + Tailscale + provisioned subdomain on `alfred.black` |
| **Updates** | `docker compose pull && up -d` on your schedule | systemd timer pulls `:latest` every 15 minutes |
| **Backups** | Roll your own (`vault_data`, `state_data`, `caddy_data`) | Nightly `restic` to Hetzner Object Storage |
| **Onboarding** | `./scripts/bootstrap.sh` then `docker compose up` | 30-min call + ~24 h to a working instance |
| **You own the VM** | Yes | No — we hold the SSH key, the LUKS key, and the Hetzner account |
| **Data sovereignty** | Yours, on your box | Yours, on a VPS we operate in EU (Germany or Finland) |
| **Cost** | VPS bill only (~$40-80/mo) | Negotiated during beta — see [Billing](/alfred-cloud/billing) |
| **Time to live** | An hour, give or take | 3 min from golden snapshot, ~20 min from scratch |
| **Federation (Alfred Prime)** | Not available | Available to select tenants |

The honest summary: **Cloud trades sovereignty for time**. If you want to inspect every container, run your own backups, and have root on the box, self-host. If you want Alfred working before lunch and don't care who runs the Linux, Cloud.

## Who Cloud is for

- People who'd self-host if it took 20 minutes and zero ongoing maintenance — but it doesn't, so they wouldn't.
- People who've tried the self-hosted path, hit an OOM or a Caddy cert wall, and decided they'd rather not.
- People who want [Alfred Prime federation](/alfred-cloud/federation) — a Cloud-only capability.

## Who Cloud is **not** for

- Anyone who needs strict on-premises hosting (regulated workloads, air-gapped networks). Self-host.
- Anyone uncomfortable with the operator holding root + LUKS key on the box where the principal's vault lives. Self-host.
- Anyone who needs a published price list before talking to a human. Pricing is negotiated during the private beta — see [Billing](/alfred-cloud/billing).
