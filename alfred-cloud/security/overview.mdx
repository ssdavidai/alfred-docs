<Note>
Alfred Cloud is the hosted, **private-beta** form of Alfred Black. Every paying subscriber gets a dedicated EU VPS — no shared compute, no shared storage, no shared database. This page is the short-version map; each row links to a deep-dive.
</Note>

## The short version

| Layer | How it's protected |
|---|---|
| **Infrastructure** | Dedicated `cx53` Hetzner Cloud VPS in the EU per tenant. No shared servers, no multi-tenancy. |
| **Data at rest** | LUKS2 (AES-256-XTS) full-disk encryption with a per-instance auto-generated passphrase. *(`packages/ctrl/src/templates/cloud-init.yaml.njk`)* |
| **Network ingress** | Hetzner Cloud Firewall allows only SSH (22), ICMP, and Tailscale UDP 41641. All Alfred services bind to `127.0.0.1`. *(`docker-compose.yaml:50–536`)* |
| **External access** | Tailscale tailnet (WireGuard mesh) and Cloudflare Tunnel only. No public IP exposure of services. |
| **API auth** | Per-tenant Bearer token (`AAS_API_KEY`), timing-safe constant-time comparison, SHA-256 hashed at rest, AES-256-GCM internal credentials. *(`packages/ctrl/src/api/auth.ts:22,77`)* |
| **Third-party credentials** | Composio holds OAuth tokens server-side. The subscriber tenant only stores connection IDs. *(`packages/ctrl/src/api/routes/integrations.ts:257–291`)* |
| **Per-tenant isolation** | `COMPOSIO_USER_ID` enforced server-side; explicit ownership verification on every connection lookup. *(`packages/ctrl/src/api/routes/integrations.ts:109,1965,3251`)* |
| **Audit** | Every authenticated API call logged. Every main-agent session captured to a queryable stream (`system-hermes-sessions`). *(`packages/ctrl/src/api/routes/admin.ts:660`)* |
| **Data residency** | EU only — Hetzner Germany (Falkenstein, Nuremberg) or Finland (Helsinki) depending on capacity at provision time. |

## The one-paragraph version

Every paying subscriber gets a **dedicated Hetzner Cloud `cx53` VPS** in the EU — not a container, not a namespace on a shared host, an entire VM. Everything that matters is on a **LUKS2-encrypted volume** mounted at `/mnt/encrypted`. The Hetzner Cloud Firewall denies every inbound port except SSH (22), ICMP for liveness checks, and WireGuard (UDP 41641) for Tailscale — every Alfred service binds to `127.0.0.1` behind that. The three shared dependencies — **Composio** (OAuth), **AgentMail** (inbound email), and the Twilio account (phone) — each have per-tenant scoping enforced server-side and re-checked on every read. The principal's password manager is a per-tenant **Vaultwarden** running inside the tenant's own Docker stack — there is no shared Vaultwarden, no shared org, no shared collection.

## What "dedicated VPS per tenant" actually means

- **Compute is yours.** A 16-vCPU, 32–64 GB `cx53` is provisioned at signup and joined to the operator's Tailscale tailnet. Your workloads never share a kernel with another tenant.
- **Storage is yours.** A Hetzner volume is created, attached, formatted with LUKS2, and mounted at `/mnt/encrypted`. The passphrase is generated post-boot via SSH (never written to Hetzner's cloud-init `user_data`, which is readable through the metadata API).
- **Database is yours.** SQLite for `alfred-state.db`, `ingest.db`, Temporal, and Vaultwarden — all on `/mnt/encrypted`. Postgres for the optional Plane / Sure sidecar stacks — all on `/mnt/encrypted`. None of these are shared.
- **Vault is yours.** The principal's Markdown vault at `/mnt/encrypted/vault` is bind-mounted into every container that needs it and never copied off-host except as a `restic` snapshot encrypted with your own key.
