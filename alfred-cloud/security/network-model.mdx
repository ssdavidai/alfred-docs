<Note>
There is no public route into your Alfred Cloud tenant. The Hetzner Cloud Firewall denies every inbound port except SSH (22), ICMP for liveness checks, and WireGuard (UDP 41641) for Tailscale. Every Alfred service binds to `127.0.0.1` behind that.
</Note>

## The three ways in

| Path | Encryption | Auth | What it reaches |
|---|---|---|---|
| **Tailscale (WireGuard mesh)** | WireGuard ChaCha20-Poly1305, end-to-end | Tailscale ACL + per-node identity | `ctrl-api:3100`, `hermes:18789/18790/18791`, Temporal, Ollama, optional sidecars |
| **Cloudflare Tunnel** | TLS 1.3 to Cloudflare edge, then **outbound** WireGuard from the tunnel daemon on the tenant | Tunnel token (per-tenant), then bearer at the origin | The mcp-server's OAuth + `/mcp` routes, optionally the dashboard reverse-proxy |
| **SSH (port 22)** | OpenSSH (per-host key, per-instance ed25519 deploy key) | Public-key only — `PasswordAuthentication no`, `PermitRootLogin no`, fail2ban on top | Shell on the host |

Everything else is denied at the Hetzner Cloud Firewall, which is labelled `managed-by: alfred-ctrl` and shared across the fleet.

## The inbound port table

Concretely, here is every port on every tenant and who can reach it:

| Port | Service | Bind | Who can reach it |
|---|---|---|---|
| **22 / tcp** | SSH | `0.0.0.0` | Anyone on the internet — but only the per-instance ed25519 deploy key is authorised. fail2ban watches sshd. |
| **ICMP** | ping | — | Anyone — for liveness checks only. |
| **41641 / udp** | Tailscale WireGuard | `0.0.0.0` | Tailscale coordination + peer handshake. The actual traffic is then encapsulated WireGuard. |
| **3100 / tcp** | `ctrl-api` | `127.0.0.1` | Localhost only. Reachable externally **only** through Tailscale or Cloudflare Tunnel. |
| **18789 / tcp** | Hermes `main` profile (chat) | `127.0.0.1` | Localhost only. *(`docker-compose.yaml:303`)* |
| **18790 / tcp** | Hermes `workers` profile (background) | `127.0.0.1` | Localhost only. |
| **18791 / tcp** | Hermes `heavy` profile (Opus-class) | `127.0.0.1` | Localhost only. |
| **7233 / tcp** | Temporal gRPC | `127.0.0.1` | Localhost only. |
| **8233 / tcp** | Temporal UI | `127.0.0.1` | Localhost only. |
| **11434 / tcp** | Ollama (embeddings) | `127.0.0.1` | Localhost only. |
| **8787 / tcp** | mcp-server (Claude Custom Connector OAuth + `/mcp`) | `127.0.0.1` | Localhost only. Cloudflared exposes specific paths. |
| **8080 / tcp** | Plane proxy (when enabled) | `127.0.0.1` | Localhost only. |
| **3001 / tcp** | Sure web (when enabled) | `127.0.0.1` | Localhost only. |

The Hetzner Cloud Firewall enforces this at the network edge — port 3100 (or any other Alfred port) is **not** reachable from the public internet, full stop.

## Why everything binds to `127.0.0.1`

Every Docker service in `docker-compose.yaml` binds its host port to `127.0.0.1`. This is belt-and-braces alongside the Hetzner firewall:

1. **Hetzner firewall denies the port at the network edge.**
2. **Even if the firewall failed open**, the service would not be listening on the public interface.
3. **Even on Tailscale**, only nodes the operator explicitly added to the tailnet can reach `100.x.y.z:3100` — there is no Tailscale "open" mode.

You can verify this in the live compose file: every `ports:` mapping uses the `127.0.0.1:` host-IP prefix, and every service that doesn't need a host port doesn't declare one at all.

## Tailscale tailnet

The tenant joins the operator's Tailscale tailnet at provision time with a one-time auth key generated on the fly by the provisioner.

| Node | Identity | What it reaches |
|---|---|---|
| **Tenant VM** | `alfred-<slug>-<id>` | Itself only — Tailscale ACLs deny tenant-to-tenant traffic |
| **SaaS host** | `alfred-saas` | All tenants on `:3100` (the proxy path) |
| **Operator laptop** | per-operator | All tenants on `:3100` and `:22` (for `ssh-to-Tailscale-IP` ops access) |
| **Paired devices** | per-device | Only the principal's own tenant on `:3100` (web dashboard via Tailscale Funnel-style passthrough) |

Tailscale ACLs are the **second** isolation layer (the first being one-VM-per-tenant). A misconfigured ACL on a tenant node would still be denied at the receiving tenant's Hetzner firewall, because port 3100 is not open from the public internet.

## Cloudflare Tunnel

The Cloudflare Tunnel is **outbound-only** — the `cloudflared` daemon on the tenant initiates a long-lived connection to the Cloudflare edge, and Cloudflare routes inbound HTTPS through it. No inbound port on the tenant is open for this; the tunnel does not listen, it dials.

| Cloudflare hostname | Route | Endpoint |
|---|---|---|
| `<subdomain>.<your-domain>` | Dashboard reverse-proxy (optional, for custom domains) | `127.0.0.1:3100` on the tenant |
| `<subdomain>-mcp.<your-domain>` | Claude Custom Connector OAuth + `/mcp` | `127.0.0.1:8787` (mcp-server) |
| `<subdomain>-plane.<your-domain>` | Plane PM (when enabled) | `127.0.0.1:8080` (plane-proxy) |
| `<subdomain>-sure.<your-domain>` | Sure finance (when enabled) | `127.0.0.1:3001` (sure-web) |

Cloudflare authenticates the tunnel itself; the application layer behind it still requires the `AAS_API_KEY` Bearer token. See [Authentication](/alfred-cloud/security/authentication).

## The voice channel exception

The voice channel takes a different shape. Twilio's Media Stream WebSocket lands on `voice.alfred.black` — that hostname is **DNS-only at Cloudflare** (not proxied), because the Cloudflare WAF drops Twilio's WebSocket upgrade with error 31920. The Voice Bridge runs on the **SaaS host**, not on the tenant, and reaches into the tenant over Tailscale using a scoped bearer token that is allowlisted to exactly two routes: `GET /api/v1/phone/voice-context` and `POST /api/v1/phone/transcript`. *(`packages/ctrl/src/api/auth.ts:38–98`)*

Even if the voice bridge were compromised, the blast radius is bounded to those two endpoints — the master `AAS_API_KEY` never leaves the tenant. *(`packages/ctrl/src/api/auth.ts:19`)*

## SSH posture

SSH is the only port open to the public internet. It is hardened by cloud-init at provision time:

- **`PermitRootLogin no`** — root cannot SSH in directly; you SSH as a sudoer.
- **`PasswordAuthentication no`** — public-key only. No passwords are configured.
- **`MaxAuthTries 3`** — three failed attempts then a disconnect.
- **per-instance ed25519 host key + per-instance ed25519 deploy key** — both generated at provision time, never reused.
- **`fail2ban` on top** — repeat offenders get firewall-banned.
- **`unattended-upgrades` enabled for security packages** — OpenSSH updates roll automatically.

The deploy key lives at `data/ssh_keys/<instance-id>/id_ed25519` on the operator's machine, generated at provision time and never re-used between tenants.

## Container-level hardening

Every long-lived container runs with:

- **`no-new-privileges: true`** — `setuid` binaries cannot escalate, even if one is found inside the image.
- **`cap_drop: ALL`** with a narrow `cap_add` (e.g. `DAC_OVERRIDE`) only where required for `chown` on bind-mounts. *(`docker-compose.yaml:311`)*
- **`mem_limit` of 1–6 GB** depending on workload. The two Hermes-heavy services (`hermes`, `alfred-learn`) get 6 GB; `ctrl-api` gets 1 GB.
- **`pids_limit: 256–2048`** — caps a fork bomb's blast radius.
- **All host ports bound to `127.0.0.1`.**
- **UFW on the host** denies inbound except 22/tcp, ICMP, and 41641/udp — a defence-in-depth backstop in case the Hetzner firewall is misconfigured.
