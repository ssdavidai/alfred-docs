Alfred is configured by a **single `.env` file** at the repo root. The flow is:

<Steps>
 <Step title="Copy the template">
 `cp .env.example .env`
 </Step>
 <Step title="Fill the five required fields">
 `DOMAIN`, `ACME_EMAIL`, `OWNER_NAME`, `OPENROUTER_API_KEY`, `COMPOSIO_API_KEY`.
 </Step>
 <Step title="Run bootstrap.sh">
 `./scripts/bootstrap.sh` generates 21 auto-secrets and a `COMPOSIO_USER_ID`. Idempotent — re-running never overwrites an existing non-empty value *(scripts/bootstrap.sh:147-172)*.
 </Step>
 <Step title="docker compose up">
 `docker compose up -d`. No build step — every image is pulled.
 </Step>
</Steps>

The sections below enumerate every variable, what reads it, and what happens if it's unset.

---

## Required — bootstrap.sh fails without these

`bootstrap.sh` validates these five fields and exits 1 with the missing list if any are blank *(scripts/bootstrap.sh:71-98)*.

| Variable | Purpose | Consuming service(s) |
|----------|---------|----------------------|
| **`DOMAIN`** | The apex domain Alfred is served on. Dashboard at `https://${DOMAIN}`; sidecars at `api.`, `plane.`, `sure.`, `vault.`, `mcp.`, `sms.`, `voice.` subdomains. Point those seven A-records at the VM before `up`. | caddy, web, web-client, ctrl-api, mcp-server, vaultwarden, plane-api, sure-web, vexa-dashboard |
| **`ACME_EMAIL`** | Contact email for Let's Encrypt certificate registration. ACME notices (renewal failures, revocations) go here. | caddy |
| **`OWNER_NAME`** | The principal's display name (shown across the dashboard and brief). | init, mcp-server, web |
| **`OPENROUTER_API_KEY`** | Primary model routing for Hermes and alfred-learn (model IDs in `HERMES_*_MODEL`). | hermes, alfred-learn |
| **`COMPOSIO_API_KEY`** | Third-party app integrations (Gmail, Stripe, Notion, Slack, …) used by the `execute` MCP app and onboarding's email backfill. | init, alfred-learn, ctrl-api, mcp-server |

<Note>`.env.example` lists `ANTHROPIC_API_KEY` under the same "USER MUST FILL — required" header *(.env.example:25-26)*, but `bootstrap.sh:71-77` does NOT validate it. Anthropic is genuinely optional — set it only if you want a direct Anthropic route bypassing OpenRouter for the heavy profile.</Note>

### Strongly recommended (warn, not fail)

| Variable | Purpose | Consequence if unset |
|----------|---------|----------------------|
| **`OWNER_EMAIL`** | The principal's primary email address. Load-bearing for: first-brief email sender + sender-allowlist, cross-tenant ingest guard, Sure's first-boot owner account, Vexa attendee matching *(.env.example:81-87)*. The code also mirrors it to `ALFRED_OWNER_EMAIL` for `transcript.py`. | First-brief email never reaches the inbox; ingest guard fails open. `bootstrap.sh:107-111` warns. |

## Auto-generated by bootstrap.sh

`bootstrap.sh` appends each of these with `openssl rand -hex 32` if absent or empty, and never overwrites an existing non-empty value *(scripts/bootstrap.sh:115-172)*. **Do not fill them by hand.**

### Core platform secrets (8)

| Variable | Purpose | Consuming service(s) |
|----------|---------|----------------------|
| `AAS_API_KEY` | Bearer token shared between web → ctrl-api and mcp-server → ctrl-api. The whole HTTP-MCP authority chain hinges on this. | web, ctrl-api, mcp-server, alfred-learn |
| `COLUMN_ENCRYPTION_KEY` | AES-256-GCM key for the web app's `OAuthCredential` token encryption at rest (Composio refresh tokens, Google tokens, …). | web |
| `JWT_SECRET` | Wasp session JWT signing secret. | web |
| `HERMES_API_SERVER_KEY` | Hermes gateway API-server key, shared by all three profiles (main/workers/heavy). Written to `/alfred-data/.gateway-token` by the init container. | hermes, alfred-learn, init |
| `WEB_DATABASE_PASSWORD` | Postgres password for the Wasp web app database (`web-db`). | web, web-db |
| `VAULTWARDEN_ADMIN_TOKEN` | Vaultwarden `/admin` token. | vaultwarden, vault-signup, vault-cli |
| `VAULTWARDEN_BW_PASSWORD` | The `bw serve` sidecar's unlock password. Vaultwarden owner account is created with this on first boot. | vault-signup, vault-cli |
| `MCP_APPROVAL_SECRET` | The mcp-server bearer + HTML-form approval secret. Granting this to a client = granting full OAuth-token capability *(packages/mcp-server/src/index.ts:210-242)*. | mcp-server, voice-bridge |

### Composio user-id (not a random secret)

| Variable | Purpose | Consuming service(s) |
|----------|---------|----------------------|

| `DJANGO_SECRET_KEY` | Plane backend Django secret. | plane-api, plane-worker, plane-beat, plane-migrator, plane-init |
| `POSTGRES_PASSWORD` | Plane Postgres password (database name `plane`, user `plane`). | plane-db, plane-api, plane-worker, plane-beat, plane-migrator, plane-init |
| `REDIS_PASSWORD` | Plane Valkey (Redis) + RabbitMQ password — same secret, both services. | plane-redis, plane-mq, plane-api, plane-worker, plane-beat, plane-migrator, plane-live, plane-init |

### Sure (4)

| Variable | Purpose | Consuming service(s) |
|----------|---------|----------------------|
| `SURE_SECRET_KEY_BASE` | Rails `SECRET_KEY_BASE` for the Sure app. | sure-web, sure-worker, sure-init |
| `SURE_POSTGRES_PASSWORD` | Sure Postgres password. | sure-db, sure-web, sure-worker, sure-init |
| `SURE_REDIS_PASSWORD` | Sure Valkey (Redis) password. | sure-redis, sure-web, sure-worker, sure-init |
| `SURE_API_KEY` | 64-char hex (Sure's `SecureRandom.hex(32)` format). `sure-init` seeds this exact value into Sure's DB and ctrl-api reads it from env so the REST proxy stops returning `NOT_CONFIGURED`. | sure-init, ctrl-api |

## Optional — feature toggles & integrations

### LLM models — Hermes profiles

The three profiles each map to one OpenRouter model id. Defaults are sane current picks; override only if a model is stale or you want a different one *(.env.example:42-44)*.

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `HERMES_MAIN_MODEL` | User-facing chat — Telegram/Slack/Hermes web chat. | `x-ai/grok-4.3` | hermes (main profile, `:18789`) |
| `HERMES_WORKERS_MODEL` | Background agents (clerk, curator, janitor, distiller, ephemeral exec subagents). | `openai/gpt-4.1-nano` | hermes (workers profile, `:18790`), alfred-learn |
| `HERMES_HEAVY_MODEL` | Opus-class reasoning for onboarding + Reflection. | `anthropic/claude-opus-4-6` | hermes (heavy profile, `:18791`), alfred-learn |
| `ANTHROPIC_API_KEY` | Direct Anthropic provider — set only if you want to route the heavy profile through Anthropic directly instead of OpenRouter. | — | hermes, alfred-learn |

### Google OAuth — fully optional

With `COMPOSIO_API_KEY` set, onboarding's Gmail connect goes through Composio's managed Google OAuth (Composio's verified app, no Google Cloud client needed). Set these two only if you want either: (a) a cosmetic "Sign in with Google" login button, or (b) to drive onboarding's Gmail connect through YOUR own Google client (`gmail.readonly` scope) *(.env.example:46-58)*.

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `GOOGLE_CLIENT_ID` | Google Cloud OAuth client id. Requires a Web-application OAuth client from `console.cloud.google.com` with redirect URI `https://api.${DOMAIN}/auth/google/callback`. | — | web, ctrl-api |
| `GOOGLE_CLIENT_SECRET` | Matching client secret. | — | web, ctrl-api |

### Email delivery

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `SENDGRID_API_KEY` | Transactional email (verification, password reset). | — (signup still works in dev mode) | web |

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|

| `OPENAI_REALTIME_MODEL` | OpenAI realtime model id. | (compose default) | voice-bridge |
| `OPENAI_REALTIME_VOICE` | OpenAI realtime voice name. | (compose default) | voice-bridge |
| `TWILIO_PHONE_NUMBER` | The Twilio phone number routed to `voice.${DOMAIN}/twilio`. | — | voice-bridge |
| `TWILIO_AUTH_TOKEN` | Twilio auth token (validates inbound webhook signatures). | — | voice-bridge |
| `VOICE_BRIDGE_INTERNAL_TOKEN` | Internal bearer between voice-bridge and ctrl-api. | — | voice-bridge |

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `STEWARD_SIGNAL_EXTRACT_ENABLED` | Whether `SignalExtractWorkflow` is registered. Set to `false` to pause stream-event → signal extraction (e.g. while debugging cost). | `true` | alfred-learn |
| `STEWARD_SIGNAL_ROUTER_ENABLED` | Whether `SignalRouterWorkflow` is registered. Pause this to soak signal generation in shadow before flipping the router on. | `true` | alfred-learn |
| `STEWARD_REVERSAL_CALIBRATION_ENABLED` | Whether `ReversalCalibrationWorkflow` is registered. | unset (off) | alfred-learn |
| `STEWARD_STREAM_EVENT_PURGE_ENABLED` | Whether `StreamEventPurgeWorkflow` (7-day TTL purge for stream events) is registered. | unset (off) | alfred-learn |
| `FLEET_AUDIT_ENABLED` | Whether the daily cross-tenant fleet audit fires. Activity-invocation-time gate. | `true` | alfred-learn |
| `PLANE_SYNC_ENABLED` | Whether the three Plane two-way sync workflows are registered (forward/reverse/reconciliation). | unset (off) | alfred-learn |

### Mode flags (activity-invocation-time)

These are checked each time the corresponding activity runs. Flipping them via `/settings#agent` (which writes to `/alfred-data/settings.json`) does NOT require a restart.

| Variable | Settings key | Purpose | Default | Resolution precedence |
|----------|--------------|---------|---------|-----------------------|
| `STEWARD_LIVE_MODE` | `state_mutator_mode` | Whether `apply_state_change_v2` actually patches matter/task frontmatter (vs only writing audit). | `shadow` *(packages/learn/src/activities/state_mutator.py:183-220)* | env → settings.json → default |
| `STEWARD_SIGNAL_ROUTER_LIVE_MODE` | — (env only) | Whether `apply_signal_mutation` actually mutates (vs only audit). | `shadow` | env → default |
| `STEWARD_SIGNAL_ACTION_LIVE_MODE` | `signal_action_mode` | Whether `route_signal_action` dispatches autonomously when discretion clears the bar (vs always HUMAN). | `live` | env → settings.json → default |
| `STEWARD_SIGNAL_AUTOCREATE_TASKS` | `auto_task_create_mode` | Whether signals auto-create tasks via `create_task_from_signal`. | `live` | env → settings.json → default |
| `ALFRED_OPUS_PACKS_ENABLED` | — | Whether onboarding uses Opus-pack generators (vs rule-based fallback). | `true` | env only |

Valid mode values: `"shadow"`, `"live"`, `"live_high_confidence_only"`.

<Warning>`state_mutator_mode` defaults to `"shadow"` in code at *(packages/learn/src/activities/state_mutator.py:183-220)*; the other two `*_mode` flags default to `"live"`. The code is the source of truth.</Warning>

### Compose & URL plumbing

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `COMPOSE_DIR_HOST` | Host filesystem path of the compose dir (the dir holding `.env` and `docker-compose.yaml`). Bind-mounted into ctrl-api at `/srv/alfred-black` so it can read/write `.env` and shell out to `docker compose`. | `/opt/alfred` | ctrl-api |
| `TENANT_BASE_URL` | The tenant's public base URL. ctrl-api uses it to build absolute webhook URLs (OMI, custom webhooks); unset → URLs come back null and integrations are unusable. | `https://${DOMAIN}` | ctrl-api |
| `SAAS_HOST` | Fallback when `TENANT_BASE_URL` is absent. Override only when serving Alfred across multiple hosts. | `https://${DOMAIN}` | ctrl-api |
| `ALFRED_LEARN_ENABLED` | Master switch for the alfred-learn worker. Set to `false` to keep the container idle. | `true` | alfred-learn |
| `DISPATCH_USE_EPHEMERAL_EXECUTOR` | Whether autonomous dispatches spawn ephemeral exec subagents (vs running in-process). | (compose default) | alfred-learn |

### Telegram / Slack

`TELEGRAM_BOT_TOKEN` is intentionally **not** passed through env — Telegram pairing flows through Hermes' main-profile config rendered by the init container, not via env. Same for Slack. Set up channels via the dashboard once Alfred is running rather than through `.env`.

## Resolution precedence — env vs settings.json vs default

For the three UI-toggleable mode flags above, ctrl-api / alfred-learn resolve in this order *(packages/learn/src/activities/signal_actions.py:90-182)*:

1. **Environment variable** (override — for emergencies / declarative deploys).
2. **`/alfred-data/settings.json` key** (UI toggle on `/settings#agent` persists here).
3. **Default**.

Any unrecognised value → log a warning, fall back to default.

## Notes on specific variables

- **`ANTHROPIC_API_KEY`** — `.env.example` shows it under the "USER MUST FILL — required" header, but `bootstrap.sh` does not enforce it; it is optional.
- **`AAS_HOST` / `AAS_PORT`** — set in compose but not read from `.env`; ctrl-api gets them from compose-internal defaults *(docker-compose.yaml:401-402)*.
- **`ALFRED_OWNER_EMAIL`** — set by compose by mirroring `OWNER_EMAIL`. `transcript.py` reads it; everywhere else reads `OWNER_EMAIL` directly.

## Tip — generate a fresh secret on the fly

To rotate one auto-generated secret without re-running bootstrap.sh, blank the field in `.env` and re-run:

```bash
sed -i '' 's/^AAS_API_KEY=.*$/AAS_API_KEY=/' .env
./scripts/bootstrap.sh
docker compose up -d --force-recreate
```

bootstrap is idempotent — present non-empty values are kept, blank ones get a fresh `openssl rand -hex 32`.

<Warning>Rotating `AAS_API_KEY`, `HERMES_API_SERVER_KEY`, or `MCP_APPROVAL_SECRET` invalidates every active session that depends on them — the web client, every connected MCP client (Claude.ai connectors), and Hermes-paired devices. Rotate during downtime.</Warning>
