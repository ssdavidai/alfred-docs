Alfred is configured by a **single `.env` file** at the repo root. The flow is:

<Steps>
 <Step title="Copy the template">
 `cp .env.example .env`
 </Step>
 <Step title="Fill the five required fields">
 `DOMAIN`, `ACME_EMAIL`, `OWNER_NAME`, `OPENROUTER_API_KEY`, `COMPOSIO_API_KEY`.
 </Step>
 <Step title="Run bootstrap.sh">
 `./scripts/bootstrap.sh` generates 21 auto-secrets and a `COMPOSIO_USER_ID`. Idempotent — re-running never overwrites an existing non-empty value *(scripts/bootstrap.sh:147-172)*.
 </Step>
 <Step title="docker compose up">
 `docker compose up -d`. No build step — every image is pulled.
 </Step>
</Steps>

The sections below enumerate every variable, what reads it, and what happens if it's unset.

---

## Required — bootstrap.sh fails without these

`bootstrap.sh` validates these five fields and exits 1 with the missing list if any are blank *(scripts/bootstrap.sh:71-98)*.

| Variable | Purpose | Consuming service(s) |
|----------|---------|----------------------|
| **`DOMAIN`** | The apex domain Alfred is served on. Dashboard at `https://${DOMAIN}`; sidecars at `api.`, `plane.`, `sure.`, `vault.`, `mcp.`, `sms.`, `voice.` subdomains. Point those seven A-records at the VM before `up`. | caddy, web, web-client, ctrl-api, mcp-server, vaultwarden, plane-api, sure-web |
| **`ACME_EMAIL`** | Contact email for Let's Encrypt certificate registration. ACME notices (renewal failures, revocations) go here. | caddy |
| **`OWNER_NAME`** | The principal's display name (shown across the dashboard and brief). | init, mcp-server, web |
| **`OPENROUTER_API_KEY`** | Primary model routing for Hermes and alfred-learn (model IDs in `HERMES_*_MODEL`). | hermes, alfred-learn |
| **`COMPOSIO_API_KEY`** | Third-party app integrations (Gmail, Stripe, Notion, Slack, …) used by the `execute` MCP app and onboarding's email backfill. | init, alfred-learn, ctrl-api, mcp-server |

<Note>`.env.example` lists `ANTHROPIC_API_KEY` under the same "USER MUST FILL — required" header *(.env.example:25-26)*, but `bootstrap.sh:71-77` does NOT validate it. Anthropic is genuinely optional — set it only if you want a direct Anthropic route bypassing OpenRouter for the heavy profile.</Note>

### Strongly recommended (warn, not fail)

| Variable | Purpose | Consequence if unset |
|----------|---------|----------------------|
| **`OWNER_EMAIL`** | The principal's primary email address. Load-bearing for: first-brief email sender + sender-allowlist, cross-tenant ingest guard, Sure's first-boot owner account, Recall.ai attendee matching *(.env.example:81-87)*. The code also mirrors it to `ALFRED_OWNER_EMAIL` for `transcript.py`. | First-brief email never reaches the inbox; ingest guard fails open. `bootstrap.sh:107-111` warns. |

## Auto-generated by bootstrap.sh

`bootstrap.sh` appends each of these with `openssl rand -hex 32` if absent or empty, and never overwrites an existing non-empty value *(scripts/bootstrap.sh:115-172)*. **Do not fill them by hand.**

The three profiles each map to one OpenRouter model id. Defaults are sane current picks; override only if a model is stale or you want a different one *(.env.example:42-44)*.

|----------|---------|---------|----------|

| `HERMES_WORKERS_MODEL` | Background agents (clerk, curator, janitor, distiller, ephemeral exec subagents). | `openai/gpt-4.1-nano` | hermes (workers profile, `:18790`), alfred-learn |

| `GOOGLE_CLIENT_SECRET` | Matching client secret. | — | web, ctrl-api |

### Voice — Twilio + OpenAI Realtime

The voice-bridge service connects Twilio Media Streams to OpenAI's gpt-realtime model. Without these set, the voice subdomain (`voice.${DOMAIN}`) still serves a health endpoint but no calls go through.

| Variable | Purpose | Default | Consumer |
|----------|---------|---------|----------|
| `OPENAI_API_KEY` | OpenAI API key (separate from the OpenRouter routing). Required for the realtime voice bridge. | — | voice-bridge |
| `OPENAI_REALTIME_MODEL` | OpenAI realtime model id. | `gpt-realtime-2` *(packages/voice-bridge/src/config.ts:46)* | voice-bridge |
| `OPENAI_REALTIME_VOICE` | OpenAI realtime voice name. | `cedar` *(packages/voice-bridge/src/config.ts:47)* | voice-bridge |
| `OPENAI_REALTIME_BASE_URL` | Override for the OpenAI Realtime WebSocket base URL. Production leaves this empty and points at `wss://api.openai.com/v1/realtime`; tests set it to a local mock server emulating `session.created` / `session.updated` to validate the connect-handshake. | `wss://api.openai.com/v1/realtime` *(packages/voice-bridge/src/config.ts:52)* | voice-bridge |
| `TWILIO_PHONE_NUMBER` | The Twilio phone number routed to `voice.${DOMAIN}/twilio`. | — | voice-bridge |
| `TWILIO_AUTH_TOKEN` | Twilio auth token (validates inbound webhook signatures). | — | voice-bridge |
| `VOICE_BRIDGE_INTERNAL_TOKEN` | Internal bearer between voice-bridge and ctrl-api. Path-allowlisted on the ctrl-api side to a read-only catalogue plus the two phone routes and the Composio dispatch — see `VOICE_BRIDGE_ALLOWLIST` / `VOICE_BRIDGE_PATTERN_ALLOWLIST` below. | — | voice-bridge, ctrl-api |
| `VOICE_BRIDGE_DEBUG` | Set `1` to log verbose realtime-socket breadcrumbs (`session.update` shape, ACK timings, etc.). | `0` *(packages/voice-bridge/src/openai-realtime.ts:71)* | voice-bridge |
| `VOICE_ALLOWED_CALLERS` | Comma-separated allowlist of caller numbers (E.164). | — | voice-bridge |
| `VOICE_ALLOW_ALL_CALLERS` | Set `1` to bypass the allowlist (development only). | — | voice-bridge |
| `MCP_EXTERNAL_SERVERS` | Optional comma-separated `name=url[=bearer]` pairs wiring extra MCP servers into voice-bridge alongside the six baked-in ones (e.g. tenant-specific surfaces like `cdsk=https://joe.ngrok.pizza/mcp/mcp`). External servers are passed through unfiltered to the realtime tool catalog — the curated allowlist below applies only to the six built-in apps. | — | voice-bridge |

The voice service has hardcoded operational limits: `MAX_CALL_SECONDS=1800`, `IDLE_HANGUP_SECONDS=60` *(docker-compose.yaml:607-608)*.

The realtime agent's MCP tool surface is curated by `VOICE_ALLOWED_MCP_TOOLS`, a tight allowlist of 22 entries baked into `packages/voice-bridge/src/mcp-clients.ts:253-279` (alfred read/write + hermes scheduling + execute list-connections). This keeps `session.instructions + tools` under OpenAI Realtime's ~16,384-token ceiling, which a full 157-tool surface would silently truncate. To change the curated set, edit the constant directly; it is not an environment variable today.

The ctrl-api side enforces a per-route allowlist for `VOICE_BRIDGE_INTERNAL_TOKEN`:

- **`VOICE_BRIDGE_ALLOWLIST`** — exact-match `METHOD:/path` pairs *(packages/ctrl/src/api/auth.ts:67-114)*. Today: the two phone routes (`/phone/voice-context`, `/phone/transcript`), the Composio dispatch (`/integrations/execute`), and the parameterless read surface (`/briefings`, `/vault/context`, `/vault/search`, `/vault/index`, `/vault/schema`, `/vault/inbox`, `/vault/graph`, `/vault/nebula-data`, `/decisions`, `/decisions/in-flight`, `/matters`, `/chores`, `/chore-actions`, `/workflows`, `/schedules`, `/state/signals`, `/state/observations`, `/admin/needs-attention`, `/learning/{status,observations,instincts,reflections,sessions}`).
- **`VOICE_BRIDGE_PATTERN_ALLOWLIST`** — anchored regexes for `:id`-style routes (`/briefings/:slugDate`, `/decisions/:id`, `/vault/list/:type`, `/vault/records/*`, `/matters/:id`, `/chores/:slug{,/runs,/source}`, `/workflows/:wfId{,/history}`, `/schedules/:schId`, `/state/{signals,observations}/:id`, `/learning/{observations,instincts}/:id`) *(packages/ctrl/src/api/auth.ts:126-161)*. No prefix inheritance, no wildcard between segments.

Both lists are read-only by design. Writes intentionally go through MCP (`alfred__act_on_decision`, `alfred__notify_principal`, `alfred__create_vault_record`, …) so a compromise of voice-bridge bounds blast radius to observable state.

## Resolution precedence — env vs settings.json vs default

For the three UI-toggleable mode flags above, ctrl-api / alfred-learn resolve in this order *(packages/learn/src/activities/signal_actions.py:90-182)*:

1. **Environment variable** (override — for emergencies / declarative deploys).
2. **`/alfred-data/settings.json` key** (UI toggle on `/settings#agent` persists here).
3. **Default**.

Any unrecognised value → log a warning, fall back to default.

## Notes on specific variables

- **`ANTHROPIC_API_KEY`** — `.env.example` shows it under the "USER MUST FILL — required" header, but `bootstrap.sh` does not enforce it; it is optional.
- **`AAS_HOST` / `AAS_PORT`** — set in compose but not read from `.env`; ctrl-api gets them from compose-internal defaults *(docker-compose.yaml:401-402)*.
- **`ALFRED_OWNER_EMAIL`** — set by compose by mirroring `OWNER_EMAIL`. `transcript.py` reads it; everywhere else reads `OWNER_EMAIL` directly.

## Tip — generate a fresh secret on the fly

To rotate one auto-generated secret without re-running bootstrap.sh, blank the field in `.env` and re-run:

```bash
sed -i '' 's/^AAS_API_KEY=.*$/AAS_API_KEY=/' .env
./scripts/bootstrap.sh
docker compose up -d --force-recreate
```

bootstrap is idempotent — present non-empty values are kept, blank ones get a fresh `openssl rand -hex 32`.

<Warning>Rotating `AAS_API_KEY`, `HERMES_API_SERVER_KEY`, or `MCP_APPROVAL_SECRET` invalidates every active session that depends on them — the web client, every connected MCP client (Claude.ai connectors), and Hermes-paired devices. Rotate during downtime.</Warning>
