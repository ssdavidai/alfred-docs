title: "ctrl-api routes"
description: "Every HTTP route on the dashboard backend."
---

`ctrl-api` is the Node 22 single-binary HTTP server that backs the Alfred Black dashboard, the Wasp web app, the Hermes MCP servers, and every internal write to `alfred-state.db` / `ingest.db` / the vault. It boots from `dist/api.mjs` (a standalone esbuild bundle of `src/api/standalone.ts`) and listens on `AAS_PORT` (default `3100`) with `AAS_API_KEY` as the bearer token *(packages/ctrl/src/api/standalone.ts:1-94)*.

The route registry is split across **55 route files** under `packages/ctrl/src/api/routes/` and exposes **roughly 425 HTTP endpoints** (counted by `addRoute(...)` calls). All routes are mounted under `/api/v1/`.

<Note>
**Authentication.** Every route requires `Authorization: Bearer ${AAS_API_KEY}` except `GET /api/v1/admin/health` (the liveness probe). The voice-bridge container uses a scoped `VOICE_BRIDGE_INTERNAL_TOKEN` for `/api/v1/phone/voice-context` only.
</Note>

<Tip>
This page enumerates every public route grouped by surface. For the body-shape rules that bit production (the vault `PATCH` wrapper, the decision `state: open` invariant, the mode-flag precedence) see the inline notes inside each accordion.
</Tip>

## Storage architecture (one-paragraph recap)

Four stores, one writer per store *(packages/ctrl/src/db/state.ts, ingest.ts, cold.ts; packages/ctrl/src/db/schema.sql:1-25)*:

| Store | File | Sole writer | Purpose |
|---|---|---|---|
| 1. Vault | `/vault/*.md` | ctrl-api (delegates to `alfred vault edit` daemon) | Principal-facing markdown |
| 2. `alfred-state.db` | `/state-data/alfred-state.db` | ctrl-api | Working memory: signals, observations, audit, links, vault index, embeddings |
| 3. `cold.db` | `/cold-data/cold.db` | ctrl-api (compactor) | Forensic long tail (zstd-compressed) |
| 4. `ingest.db` | `/ingest-data/ingest.db` | ctrl-api | Raw inbound stream events (7-day TTL) |

`alfred-learn`, the `alfred` vault daemon, and every Hermes profile write to ctrl-api over HTTP rather than touching SQLite directly. This is the single-writer discipline that keeps the vault index and the audit ledger consistent.

## Vault surface

The vault holds the **12 canonical record types** *(packages/ctrl/src/db/promotionContract.ts:29-42)*: `matter`, `task`, `note`, `person`, `org`, `place`, `asset`, `chore`, `instinct`, `decision`, `briefing`, `daybook`. Plus the singletons `SOUL.md` / `RULES.md` and the ctrl-api-managed dirs `_templates/` and `needs_attention/` *(promotionContract.ts:52-69)*.

Every write route enforces `assertCanonicalVaultPath()` *(promotionContract.ts:149-178)* before any filesystem touch. Demoted types (signal, observation, *-action, stream_event, …) raise `HTTP 422 PROMOTION_CONTRACT_VIOLATION` with a `destination` field pointing at the correct store *(promotionContract.ts:75-119)*.

<Warning>
**PATCH body wrapper.** A bare field-keyed body to `PATCH /api/v1/vault/records/*` returns `200` with no effect — the `hasCliArgs` check at `vault.ts:976` short-circuits before any docker exec. You must wrap edits in one of these envelopes *(packages/ctrl/src/api/routes/vault.ts:883-1100)*:

```json
{
  "set":          { "status": "active", "owner": "alfred" },
  "append":       { "tags": "urgent", "related": "matter/foo.md" },
  "body_append":  "\n## Update\nNew details here.",
  "json_set":     { "side_effects": { "agent_dispatched": true } },
  "body_set":     "Full new body content (not yet implemented)"
}
```

`set` / `append` / `body_append` dispatch to the `alfred vault edit` CLI inside the `alfred` container. `json_set` performs a direct YAML merge in-process — use it for nested/structured values that the CLI flattens.
</Warning>

<Info>
**State-mutation gate.** If `PATCH` touches a declared `state` field on a `matter` or `task`, the route checks `STATE_CHANGE_ENFORCEMENT` *(vault.ts:901-952)*:
- unset / `"warn"` (default): log a warning, proceed.
- `"reject"`: return `403 STATE_CHANGE_REQUIRED` with the offending field list.

Manual state edits via the SaaS editor route through `POST /api/v1/state-changes` instead.
</Info>

</Accordion>

## Decisions surface

A `decision/<ts>-<short>.md` record is the first-class artefact of every human action on the Desk — every Delegate / Defer / Done / Take-mine / Noise click *(packages/ctrl/src/api/routes/decisions.ts:1-30)*.

**Lifecycle:** `open → dispatching → executing → completed` (terminal) or `reversed` *(decisions.ts:65-79)*.

<Warning>
**Always mint `state: open`.** The DecisionRouterWorkflow only fires `extract_observation_from_decision` for decisions in `state=open`. If you mint `state=completed` directly, the learning loop never closes. This is the regression caught on 2026-05-24 (CLAUDE.md §16).
</Warning>

<Accordion title="Decision routes (6)">

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/v1/decisions` | Create a decision. Body: `{intent, source, source_record, note, principal?, decision_origin?}`. Always lands in `state=open`. |
| GET | `/api/v1/decisions` | List with filters (`state`, `source`, `since`, `limit`). |
| GET | `/api/v1/decisions/in-flight` | Decisions currently awaiting an agent outcome (`state=executing`). |
| GET | `/api/v1/decisions/:id` | One decision record. |
| PATCH | `/api/v1/decisions/:id` | Partial update (`state`, `outcome_record`, `executing_at`, `completed_at`). |
| POST | `/api/v1/decisions/:id/reverse` | Flip to `state=reversed` and trigger inverse side effects. |

**Valid `intent`:** `delegate | defer | done | take_mine | noise` *(decisions.ts:81-83)*.
**Valid `source`:** `needs_attention | approval | judgment | to_do | desk_originated | pattern_proposal | instinct_fire` *(decisions.ts:84-92)*.
**Valid `principal`:** `principal | alfred` (the latter when SignalRouter fires autonomously) *(decisions.ts:98-99)*.

<Info>
**The decision-mirror recursion guard.** `/dispatch` mints a `decision/<ts>.md` so the Desk shows a unified history. </Info>

</Accordion>

## Settings surface

The three mode flags that gate Alfred's autonomy *(packages/ctrl/src/api/routes/settings.ts:56-72)*. All default `"live"` (do the thing); flipped to `"shadow"` they record what would happen but don't act.

| Key | Controls | Env override |
|---|---|---|
| `signal_action_mode` | Whether SignalRouter dispatches autonomously when discretion clears the bar. | `STEWARD_SIGNAL_ACTION_LIVE_MODE` |
| `state_mutator_mode` | Whether `state_mutator` patches matter/task frontmatter. | `STEWARD_LIVE_MODE` |
| `auto_task_create_mode` | Whether signals auto-create tasks. | `STEWARD_SIGNAL_AUTOCREATE_TASKS` |

**Read precedence** *(settings.ts:135-150)*: env var → `settings.json` → registered default. Writes are atomic (temp file + rename) to `/alfred-data/settings.json`.

## Quick reference — most-used endpoints

```http
# Sir's daily Desk write
POST /api/v1/decisions
  { "intent": "delegate",
    "source": "needs_attention",
    "source_record": "needs_attention/2026-05-24-…-abc.md",
    "note": "Reply with the call link" }

# Sir's vault edit (canonical body shape)
PATCH /api/v1/vault/records/matter/acme.md
  { "set":          { "status": "completed" },
    "append":       { "tags": "resolved" },
    "body_append":  "\n\nClosed out 2026-05-24." }

# Settings flag toggle
PUT /api/v1/settings/signal_action_mode
  { "mode": "shadow" }

POST /api/v1/state/audit
  { "action_type": "vault_write",
    "actor": "alfred",
    "summary": "Curator stitched inbox/foo.md → note/baz.md",
    "target_path": "note/baz.md" }
```
