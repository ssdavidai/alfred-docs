Alfred Black persists machine state in three SQLite files plus the markdown vault — the **four-store architecture** (`packages/ctrl/docs/STORAGE-ARCHITECTURE.md`, PLAN.md Part I). This page documents every table across the three SQLite stores, the index strategy on each, and which service owns the write handle.

<Info>
**Single-writer discipline.** ctrl-api is the **only** process with a write handle to `alfred-state.db`, `ingest.db`, and `cold.db` *(packages/ctrl/src/db/schema.sql:17-20)*. `alfred-learn`, the `alfred` vault daemon, every Hermes profile, and every Wasp web operation writes through ctrl-api HTTP routes. This eliminates SQLite multi-process write contention and makes the `vault_index` read-index structurally consistent.
</Info>

## Pragmas applied at open

ctrl-api applies these PRAGMAs on every database open *(packages/ctrl/src/db/state.ts:59-62)*:

```sql
PRAGMA journal_mode = WAL; -- concurrent readers never block the writer
PRAGMA busy_timeout = 5000; -- 5s contention absorption
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL; -- good durability, acceptable fsync batching
```

`sqlite-vec` is loaded at boot when `SQLITE_VEC_PATH` is set, and the `embedding` vec0 virtual table is created in-process (it cannot be created via a static `.sql` file because the extension must be loaded first) *(state.ts:74-98)*.

## Store 2: `alfred-state.db` — working memory

Located at `process.env.STATE_DB_PATH ?? ./data/alfred-state.db` *(packages/ctrl/src/db/state.ts:24-26)*. Schema lives at `packages/ctrl/src/db/schema.sql` (idempotent `CREATE TABLE IF NOT EXISTS`) plus numbered migrations at `packages/ctrl/src/db/migrations/`.

### `signal` — demoted signal records

Working-memory unit of inbound salience the system extracted from a stream event ("an email from X mentions deadline Y"). Never lives in the vault *(packages/ctrl/src/db/schema.sql:34-53)*.

**Columns**

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PRIMARY KEY | ULID |
| `ts` | TEXT NOT NULL | ISO-8601 creation time (TTL anchor) |
| `kind` | TEXT NOT NULL | `deadline \| mention \| request \| anomaly \| …` |
| `source` | TEXT NOT NULL | Dotted source id (e.g. `signal_extract.email`) |
| `stream_event_id` | TEXT | By-value ref into `ingest.db.stream_event` |
| `entity_ref` | TEXT | Vault path of the related record, if any |
| `matter_ref` | TEXT | Vault path of the related matter |
| `headline` | TEXT NOT NULL | |
| `body` | TEXT | Extracted detail |
| `salience` | REAL NOT NULL DEFAULT 0.5 | `[0, 1]` |
| `status` | TEXT NOT NULL DEFAULT `'open'` | `open \| routed \| dismissed \| folded \| dispatching \| routed_human \| routed_agent \| routed_suppressed \| agent_responded` |
| `payload_json` | TEXT | Full structured payload |
| `created_at`, `updated_at` | TEXT | Defaults to `datetime('now')` |

**Indexes**

```sql
idx_signal_ts ON signal(ts DESC)
idx_signal_status_ts ON signal(status, ts DESC)
idx_signal_matter ON signal(matter_ref, ts DESC)
idx_signal_kind ON signal(kind, ts DESC)
```

**TTL**: 90 days → `archive_signal` in `cold.db`.

### `link` — cross-record graph edges

An explicit, queryable edge between two records. Either endpoint may be a vault path (`matter/x.md`) or an `alfred-state.db` row id (`signal:01J…`). Replaces the implicit graph that lived in scattered frontmatter `*_ref` fields *(schema.sql:144-165)*.

**Columns**

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PRIMARY KEY | ULID |
| `ts` | TEXT NOT NULL | TTL anchor |
| `src_ref` | TEXT NOT NULL | E.g. `matter/x.md`, `signal:<id>` |
| `dst_ref` | TEXT NOT NULL | |
| `rel` | TEXT NOT NULL | `mentions \| derived_from \| resolves \| blocks \| child_of \| observed_in \| …` |
| `weight` | REAL NOT NULL DEFAULT 1.0 | |
| `payload_json` | TEXT | |
| `created_at` | TEXT | |

**Indexes**

```sql
idx_link_unique UNIQUE (src_ref, dst_ref, rel)
idx_link_src ON link(src_ref)
idx_link_dst ON link(dst_ref)
idx_link_rel ON link(rel)
```

**TTL**: 365 days → `archive_link` in `cold.db`.

### `vault_index` — read-index over the markdown vault

One row per canonical vault record. ctrl-api is the sole vault writer, so it updates this index on every write (create / edit / move / delete) — drift is structurally impossible *(schema.sql:167-190)*. A boot-time reconciler walks the vault once to catch out-of-band edits (a human editing markdown directly in Obsidian).

**Columns**

| Column | Type | Notes |
|---|---|---|
| `path` | TEXT PRIMARY KEY | Vault-relative path (e.g. `matter/acme.md`) |
| `record_type` | TEXT NOT NULL | One of the 12 canonical types |
| `title` | TEXT | |
| `status` | TEXT | `frontmatter.status` if present |
| `as_of` | TEXT | `frontmatter.as_of` if present |
| `frontmatter_json` | TEXT | Parsed frontmatter snapshot |
| `body_preview` | TEXT | First ~500 chars |
| `size_bytes` | INTEGER | |
| `mtime` | TEXT | File mtime (ISO-8601) |
| `indexed_at` | TEXT | |

**Indexes**

```sql
idx_vault_index_type ON vault_index(record_type, mtime DESC)
idx_vault_index_status ON vault_index(record_type, status)
idx_vault_index_mtime ON vault_index(mtime DESC)
```

**TTL**: none — drops only when the underlying vault record is deleted.

### `embedding_meta` + `embedding` vec0 — vector store

`embedding` is the `sqlite-vec` vec0 virtual table holding 768-dim vectors from Ollama's `nomic-embed-text` *(schema.sql:192-221, state.ts:74-98)*. vec0 holds only the vector + a rowid; `embedding_meta` carries the human-readable columns keyed by that same rowid.

**`embedding_meta` columns**

| Column | Type | Notes |
|---|---|---|
| `rowid` | INTEGER PRIMARY KEY | Shared rowid with the vec0 `embedding` table |
| `ref` | TEXT NOT NULL | Vault path or `signal:<id>` the vector embeds |
| `ref_kind` | TEXT NOT NULL | `vault \| signal \| observation` |
| `ts` | TEXT NOT NULL | ISO-8601 (TTL anchor) |
| `model` | TEXT NOT NULL DEFAULT `'nomic-embed-text'` | |
| `chunk_index` | INTEGER NOT NULL DEFAULT 0 | For chunked records |
| `text_preview` | TEXT | |
| `created_at` | TEXT | |

**vec0 DDL** (created in-process by `state.ts` after the extension loads):

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS embedding USING vec0(
 embedding float[768]
);
```

**Indexes (on `embedding_meta`)**

```sql
idx_embedding_meta_ref ON embedding_meta(ref)
idx_embedding_meta_kind ON embedding_meta(ref_kind, ts DESC)
```

## Store 4: `ingest.db` — raw inbound firehose

Located at `process.env.INGEST_DB_PATH ?? ./data/ingest.db` *(packages/ctrl/src/db/ingest.ts:16-17)*. Separated from `alfred-state.db` so a firehose burst can never take the write lock on working memory. Hard 7-day TTL — consume-then-delete by design, no archive *(packages/ctrl/src/db/ingest-schema.sql:1-22)*.

### `stream_event` — raw inbound payload

Every email, Telegram message, Slack DM, omi transcript, webhook, …

| Column | Type | Notes |
|---|---|---|
| `id` | TEXT PRIMARY KEY | ULID (also gives sequential ordering) |
| `ts` | TEXT NOT NULL | Arrival time (TTL anchor) |
| `stream` | TEXT NOT NULL | Logical stream (`email`, `telegram`) |
| `channel` | TEXT | Channel / account |
| `external_id` | TEXT | Upstream id (dedupe key) |
| `kind` | TEXT NOT NULL DEFAULT `'message'` | `message \| attachment \| webhook \| …` |
| `payload_json` | TEXT NOT NULL | Raw inbound payload |
| `processed_at` | TEXT | Set when EventProcessor consumes; `NULL` = pending |
| `processed_by` | TEXT | Consumer worker / workflow |
| `created_at` | TEXT NOT NULL | |

**Indexes**

```sql
idx_stream_event_pending ON stream_event(processed_at, ts) WHERE processed_at IS NULL
idx_stream_event_ts ON stream_event(ts)
idx_stream_event_stream ON stream_event(stream, ts DESC)
```

The partial unique index on `(stream, external_id)` is the dedupe key — re-arriving webhooks are silently dropped.

## Migrations

The migration runner (`runMigrations` in `packages/ctrl/src/db/migrate.ts`) is idempotent, transactional, and gated on the SQLite `user_version` PRAGMA. Numbered SQL files in `packages/ctrl/src/db/migrations/`:

| File | Adds | Purpose |
|---|---|---|
| `0001_fix_pack.sql` | `observation.processed_at` column + `idx_observation_processed` index | Anchor for Reflection's "has this observation been seen yet?" check. Ensures `mark_observations_processed` writes to `alfred-state.db` rather than the vault. |
| `0002_alfred_journal.sql` | `alfred_principal`, `alfred_principal_channel`, `alfred_journal` tables + indexes; bootstraps the owner principal | The continuity layer for "one Alfred" UX — bridges the per-(user, channel) Hermes sessions so the `main` profile sees a coherent conversation across channels. |

<Warning>
**Never edit a merged migration.** `schema.sql` is `CREATE-IF-NOT-EXISTS` only and cannot evolve an existing table. New columns and tables must land in a new migration file, never by mutating an old one.
</Warning>

## Quick reference — typical queries

**Find every observation tied to one matter:**

```sql
SELECT id, ts, kind, summary, confidence
FROM observation
WHERE payload_json LIKE '%"matter_ref":"matter/acme.md"%'
ORDER BY ts DESC
LIMIT 50;
```

**Cross-tier audit by actor:**

```sql
-- ctrl-api does this merge automatically at /api/v1/state/audit
SELECT id, ts, summary FROM audit WHERE actor = 'alfred'
UNION ALL
SELECT id, ts, summary FROM cold.archive_audit WHERE actor = 'alfred'
ORDER BY ts DESC LIMIT 100;
```

**Find pending stream events older than 1h (EventProcessor lag check):**

```sql
SELECT stream, COUNT(*) AS pending
FROM stream_event
WHERE processed_at IS NULL
 AND ts < datetime('now', '-1 hour')
GROUP BY stream;
```
