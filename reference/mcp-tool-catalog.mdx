Alfred Black exposes its capability surface to LLMs through **Model Context Protocol (MCP)** servers. Six apps live in the catalogue *(packages/mcp-server/src/tools/registry.ts:16-31)*; each Hermes profile currently registers **six MCP servers** — five stdio apps plus the HTTP `alfred-ctrl` proxy *(packages/hermes/hermes-config.yaml.njk:280-354)*. The sixth app (`hermes`) ships in the bundle but is not yet wired into the profile template; it is reachable via the HTTP MCP server at `mcp.{$DOMAIN}/hermes/mcp` *(packages/mcp-server/src/index.ts:299-334)*. Apps in the catalogue:

- **Six stdio apps** compiled from a single TypeScript bundle (`packages/mcp-server`) and spawned by Hermes as Node subprocesses: `alfred`, `sure`, `plane`, `vaultwarden`, `execute`, `hermes`.
- **One HTTP server** (`alfred-ctrl`) — a thin proxy that lets MCP clients reach the same ctrl-api routes that back most stdio tools.

All six stdio apps share one transport layer: `proxyToCtrl()` *(packages/mcp-server/src/tools/helpers.ts:68-96)* attaches `Authorization: Bearer ${AAS_API_KEY}` and forwards each call to ctrl-api on `:3100`. ctrl-api then talks to the real backend (filesystem, Plane REST, Vaultwarden REST, Composio v3, Sure Rails-runner, Hermes HTTP API).

The same TS bundle is also shipped as a standalone container (`alfred-mcp-server`, port `:8787`) for Claude.ai Custom Connectors *(packages/mcp-server/src/index.ts:244-334)* — `mcp.${DOMAIN}` routes through Caddy to it. Approval flows via `MCP_APPROVAL_SECRET` (timing-safe bearer match or interactive HTML form) *(packages/mcp-server/src/index.ts:210-242)*.

## alfred — vault, agents, workflows, briefings (24 tools)

**Backend**: HTTP via `proxyToCtrl()` to ctrl-api's `/api/v1/*` endpoints *(packages/mcp-server/src/tools/alfred.ts:46-562)*. Bearer auth using `AAS_API_KEY`. Backing endpoints: vault filesystem (read/write through the alfred CLI under a per-path mutex), Temporal CLI via `docker exec`, Hermes pairing CLI, ctrl-api ledger queries.

This is the Alfred Black control surface: read or write any vault record, kick off Temporal workflows, inspect the OpenClaw/Hermes gateway, and send notifications. Twenty-four tools intentionally exposed; restart / rotate-secret / fleet-pause operations are deliberately withheld from connector traffic *(packages/mcp-server/src/tools/alfred.ts:18-28)*.

## sure — personal finance (116 tools)

## vaultwarden — secrets manager (14 tools)

**Backend**: HTTP via `proxyToCtrl()` to ctrl-api's `/api/v1/vaultwarden/*`, which proxies to a long-running `bw serve` sidecar on `vault-cli:8087`, which talks to Vaultwarden's REST on `vaultwarden:80` *(packages/mcp-server/src/tools/vaultwarden.ts:1-19)*. The session is unlocked at boot using `VAULTWARDEN_BW_PASSWORD` and never re-locked.

Deliberately narrow surface (no attachment upload/download, no Send, no password history) because remote LLMs talk to this app over a 1-hour bearer token *(packages/mcp-server/src/tools/vaultwarden.ts:12-19)*. `get_vault_item` is the **only** tool in any app that returns secret values (passwords, TOTP).

Added on 2026-05-26 to support the voice agent: the realtime voice runtime delegates long-form research/composition to the text-tuned worker model, and uses scheduling for reminders. All seven tools accept an optional `profile: "main" | "workers"` arg.

## alfred-ctrl — HTTP proxy (not stdio)

The seventh MCP server registered per Hermes profile is **not** a separate process. It's an HTTP proxy declaration in each profile's `config.yaml` *(packages/hermes/init/profiles/*/config.yaml)* that points at ctrl-api directly:

```yaml
mcp:
  - name: alfred-ctrl
    type: http
    url: http://ctrl-api:3100
    auth:
      type: bearer
      token_file: /alfred-data/.gateway-token
```

Hermes calls ctrl-api over HTTP and surfaces the full ~40-route surface (vault routes, decisions, signals, observations, settings, system, …) as tools. The stdio `alfred` app above exposes a curated 24-tool subset suitable for remote LLMs — `alfred-ctrl` is the full unfiltered surface, intended for in-tenant agents (the main chat persona, ephemeral exec subagents, alfred-learn workers) where trust is much higher.

See [ctrl-api routes](/reference/ctrl-api-routes) for the complete endpoint catalogue.

## Approval flow — bearer or HTML form

The HTTP MCP server (`alfred-mcp-server`, `mcp.${DOMAIN}`) supports two auth paths *(packages/mcp-server/src/index.ts:122-242)*:

<Tabs>
<Tab title="Human (claude.ai)">
1. `POST /<app>/mcp` → 401 with `WWW-Authenticate`.
2. Browser redirected to `/authorize`.
3. Sir enters `MCP_APPROVAL_SECRET` on an HTML form.
4. Form posts to `/approve` with `secret` + `client_id` + `code_challenge` + `app_id` + `redirect_uri`.
5. Server validates the secret (timing-safe compare), issues an auth code, redirects back with code.
6. Token good for **1 hour** *(packages/mcp-server/src/oauth/provider.ts:35)*.
</Tab>
<Tab title="Programmatic (bearer)">
1. Set `Authorization: Bearer ${MCP_APPROVAL_SECRET}`.
2. Middleware short-circuits the OAuth verifier and synthesises `req.auth` directly.
3. Blast radius is the same as a full OAuth token (the secret can already mint one), but the round-trip is gone.
</Tab>
</Tabs>

Stdio apps (the 6 spawned by Hermes) don't use this flow — they inherit auth from the parent Hermes profile via the gateway token at `/alfred-data/.gateway-token`.

## Cross-cutting notes

<Info>

- **Tool dispatch is transport-agnostic** *(packages/mcp-server/src/tools/types.ts:43-51)*. Every tool defines `inputSchema` (Zod) + `buildRequest` (returns method + path + body/query). The same definitions serve both stdio child processes (Hermes) and the HTTP server (Claude connector).
- **The HTTP server is a per-tenant container**; stdio apps are per-profile child processes inside Hermes. Both run on the same compose network and talk to the same ctrl-api.
- **No tool returns secret values except `get_vault_item`**. Even `vaultwarden_status` and `list_vault_items` omit passwords/TOTP.
- **`composio_execute` is the explicit Composio surface**; do not use it for Telegram or Slack notifications — those are Hermes main-profile channels reached via `notify_principal`.
- **Sure mutations have two backings**: `Backing: REST` is straightforward REST; `Backing: Rails-runner` is a sandboxed `bin/rails runner` shell-out that ctrl-api uses for endpoints Sure's REST doesn't expose. Both go through the same MCP call.

</Info>
