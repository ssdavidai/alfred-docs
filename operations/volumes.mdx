title: "Volumes"

---

`docker-compose.yaml` declares ~23 named volumes in the default profile *(`docker-compose.yaml:1491-1514`)*. They're created on first `docker compose up` and persist across container restarts. This page maps each one to the service that owns it, what's inside, and how urgently you should back it up.

<Note>
**Single-writer discipline.** Most volumes have exactly one container with a write mount. The few exceptions (`alfred_data`, `hermes_data`, `vault_data`) are coordinated through `init` doing the scaffold once and `ctrl-api` doing all subsequent writes through HTTP endpoints, with other readers mounted read-only or write-coordinated. See [storage architecture](/architecture/storage-architecture).
</Note>

## Inspecting volume contents

The volumes live under `/var/lib/docker/volumes/alfred-black_<name>/_data/` on the host. To poke at them:

```bash
# Quick read from inside the writer container
docker compose exec ctrl-api ls -la /state

# Browse from the host (root)
ls /var/lib/docker/volumes/alfred-black_vault_data/_data/

# Disk usage by volume
docker system df -v | head -50
```

For SQLite-backed volumes (`state_data`, `ingest_data`, `temporal_data`, `web_db_data`), prefer connecting to the live writer over the gateway API or with `sqlite3` inside the container — the database file on the host is WAL-mode and can be in an inconsistent state mid-checkpoint.

## Removing volumes (destructive)

`docker compose down` keeps volumes; `docker compose down -v` deletes them. The latter is the **only** way to wipe a tenant fully.

<Warning>
`docker compose down -v` deletes everything — vault, certs, learning history, the entire Vaultwarden vault. Triple-check the directory you're in. If you're testing on a throwaway VM and you mean to nuke and start over, also run `docker volume prune -f` afterwards to clean up any orphaned volumes from previous compose project names.
</Warning>

To recreate after a wipe:

```bash
docker compose down -v
./scripts/bootstrap.sh # re-validates .env (auto-secrets are kept since they're in .env, not the volumes)
docker compose up -d
```

The `init` container scaffolds fresh volumes; first signup at `https://${DOMAIN}` re-establishes the owner.
