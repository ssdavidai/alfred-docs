`/channels` is one card per door into Alfred. Same Alfred, same memory; the page just lets the principal pick which medium fits the moment *(packages/web/src/dashboard/ChannelsPage.tsx)*. Each card is self-contained: live status from a dedicated `get*ChannelStatus` Wasp query, provisioning form when unconfigured, test-message + disconnect controls when running.

## Status pills

Every card carries one of: **Connected** (active), **Not connected** (available), **Starting** (a provisioning save in flight, waiting on Hermes to pick up the new config), **Needs attention** (an error state), **Coming soon** (placeholder). The pill color flips brass for active/error, marginalia for the rest *(ChannelsPage.tsx:511-549)*.

## Per-channel provisioning

<AccordionGroup>
 <Accordion title="Email (AgentMail)">
 Single field: paste the AgentMail API key. `provisionEmail` writes the credential and provisions the inbox; the card flips to `Connected` showing the assigned `inbox_address` *(ChannelsPage.tsx:184-201)*. Forwarded mail lands in the vault's `inbox/` folder.
 </Accordion>

 <Accordion title="SMS (Twilio)">
 Three fields: Account SID (`AC` + 32 hex), Auth Token (32 hex), Twilio phone number in E.164 format. Optional fold-out: a comma-separated `SMS_ALLOWED_USERS` allowlist *(ChannelsPage.tsx:1498-1569)*. Once running, the principal can flip between **Open** (anyone can text) and **Allowlist** (only listed E.164 numbers) via the shared `AllowlistEditor` *(ChannelsPage.tsx:1336-1496)*. `Send test SMS` confirms Twilio accepts the message.
 </Accordion>

 <Accordion title="Voice (voice-bridge)">
 Read-only: voice reuses the SMS section's Twilio credentials. Surfaces deploy-readiness only; the principal manages only the **Open / Allowlist** of authorised callers via the same `AllowlistEditor` *(ChannelsPage.tsx:348-355)*.
 </Accordion>

 <Accordion title="Telegram">
 Single field: bot token from `@BotFather` in shape `digits:secret`. `setTelegramBotToken` persists; the card moves through `configured_starting → configured_running` as Hermes restarts to pick up the token *(ChannelsPage.tsx:572-880, packages/web/src/dashboard/telegramCardCore.ts)*. When running, every paired chat is listed with a per-chat Revoke; `Send test message` confirms delivery.
 </Accordion>

 <Accordion title="Slack">
 Two-token Socket-Mode flow. Step 1: copy the auto-generated app manifest from `getSlackManifest` and paste it into `api.slack.com/apps → Create New App → From an app manifest`. Step 2: paste the Bot User OAuth Token (`xoxb-…`) and an App-Level Token (`xapp-…` with `connections:write`). Optional Phase-2 fields: home channel, allowed users, allowed channels *(ChannelsPage.tsx:884-1280)*.
 </Accordion>

 <Accordion title="OMI">
 The transcription path needs a Groq API key (stored server-side in Vaultwarden; `alfred-learn` reads it at transcription time). Card states: `unconfigured` (no Groq key) → `needs_groq_key` (key invalid) → `configured` (working) → `error` *(packages/web/src/dashboard/omiCardCore.ts)*. Pair the wearable itself via [Connections](/surfaces/connections) — `alfred-omi` is the synthetic slug that mints the device's audio endpoint.
 </Accordion>

 <Accordion title="Recall.ai (meeting bot)">
 Two-step API key paste: validate against Recall's `/v2/health`, then persist into Vaultwarden + restart ctrl-api/alfred-learn so activities pick up the client. Then a dial form: region / bot name / auto-join policy / per-meeting cap / monthly hours ceiling / wake word / announce-on-join / cost-alert thresholds. Live "active bots" panel with mid-meeting Terminate. Full writeup: [Recall.ai](/integrations/recall). Replaces the retired Vexa stack — see [Vexa (retired)](/integrations/vexa).
 </Accordion>

 <Accordion title="Home Assistant">
 Paste your HA URL + a long-lived access token (LLAT). The LLAT lives in Vaultwarden, never in state.db columns. Five states map to ctrl-api's `/api/v1/channels/ha/status`: `unconfigured` / `connecting` / `connected` (with registry counts) / `error` (verbatim `last_error`) / `disconnected`. Wires the 26 `ha__*` MCP tools into Hermes-main; the loop-guard contract means Alfred's own writes don't echo back as principal-relevant signals. Full writeup: [Home Assistant](/integrations/home-assistant).
 </Accordion>

 <Accordion title="HA Conversation">
 Mints a tenant-scoped channel token (`ha_<token>`) the HACS-installed `alfred-ha` integration pastes into HA. Once installed, Alfred appears on **Settings → Voice assistants → Conversation agent**. Each HA Assist turn round-trips to `/api/v1/channels/ha/turn` with `Authorization: Bearer ha_…`, rate-limited 30/min per `haInstallId`, forwarded to Hermes-main with session key `ha-<haInstallId>` for continuity.
 </Accordion>

 <Accordion title="Voice satellites + wake words">
 Read-only diagnostic card. Lists every voice satellite registered against this tenant, the wake-word model loaded on each, and whether the satellite fires only on Wyoming acknowledgement. Today the production path is openWakeWord via the Wyoming addon with the `alfred.tflite` model in `/share/openwakeword/`; the long-term path is microWakeWord directly on the ESP32 once a model exists.
 </Accordion>

 <Accordion title="Tailscale">
 Off-by-default sidecar. Click Connect → ctrl-api shells `docker compose --profile tailscale up -d` and runs `tailscale up`, captures the one-time auth URL, returns it to the card. Visit the URL in your browser; the card polls `/status` every 3 s and pivots to `connected` once the node is authorised. Connected view: MagicDNS hostname, advertised routes, peer count, Disconnect. Full writeup: [Tailscale](/integrations/tailscale).
 </Accordion>

 <Accordion title="Paperclip">
 Setup is the one-time API-key paste of a board key from a configured Paperclip company. When the principal sets up Paperclip fresh, the `paperclip-init` container full-seeds the company + CEO agent + redeemed invite, then writes the board key into each Hermes profile's `.env` — the card just verifies. Inbound channel: Paperclip's HTTP adapter HMAC-signs heartbeats to `/api/v1/channels/paperclip/heartbeat`; ctrl-api verifies, journals, forwards to Hermes-main. See [Paperclip](/integrations/paperclip).
 </Accordion>

 <Accordion title="Terminal (SSH + Hermes)">
 Pure-read card. `getSshInfo` returns `{hostname, port, user, pubkey, hermes_exec}` — the public key for the principal to drop into `authorized_keys`, plus the exact `docker exec … hermes` command to talk to Alfred from a shell. Both have copy/download affordances *(ChannelsPage.tsx:407-509)*. The empty state points at `/settings#credentials`.
 </Accordion>
</AccordionGroup>

## How the cards talk to ctrl-api

Each card is backed by a tightly-scoped pair of Wasp queries and actions that proxy `/api/v1/channels/<channel>/*` on ctrl-api. The page imports **25+ operations** in one block *(ChannelsPage.tsx:9-42)*. The state-derivation logic for the four newer cards (Telegram, Slack, SMS, Voice, OMI, Terminal) is split into pure `<channel>CardCore.ts` files so the visual-state machines are unit-tested without React or Wasp imports — useful when changing the card's empty/error copy without booting the SPA.

<Note>
Tokens for SMS, Slack, Telegram are written to Vaultwarden and reflected into `.env`. A save triggers a Hermes restart so the new credentials are picked up by the running profile. The "Starting" pill is the visible window of that restart *(ChannelsPage.tsx:584-616, 949-969)*.
</Note>

## Authorisation discipline

SMS and Voice carry an **Open / Allowlist** radio that controls who can reach Alfred through Twilio. The two channels share one editor component because the UX is identical (radio + CSV of E.164 numbers); only the verb ("text" / "call") and the wire field name differ. Save is disabled in `Allowlist` mode when the list is empty — preventing the principal from accidentally locking themselves out *(ChannelsPage.tsx:1336-1496)*.

Slack and Telegram have their own per-chat or per-user revoke flows on the live card. Email has no allowlist — any forwarded message lands.

## Implementation notes

- The Phone card reads `twilio_phone_number` / `allowed_users` keys from ctrl-api so the card reflects the actual provisioning state on disk *(ChannelsPage.tsx:85-89)*.
- Email status reads `inbox_address`, which is only present once `configured: true` *(ChannelsPage.tsx:77-80)*.
- The Terminal `hermes_exec` command is composed by ctrl-api — never reconstructed client-side — so it stays correct when container names change *(packages/web/src/dashboard/terminalCardCore.ts)*.
