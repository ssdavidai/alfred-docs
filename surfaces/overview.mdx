Alfred Black exposes its day-to-day surface as **fourteen pages** in a Wasp single-page app *(packages/web/main.wasp:191-1531)*. Every URL maps to one React component under `packages/web/src/` and pulls its data through the ctrl-api proxy on port 3100. The vocabulary on this page is the source of truth: use it in code comments, agent prompts, and documentation.

## Aliases and redirects

A few alternate URLs resolve as thin redirects so bookmarks and email links keep flowing:

| Alias | Resolves to | Redirect component |
|---|---|---|
| `/dashboard` | `/desk` | `DashboardPage.tsx` |
| `/triage` | `/desk` | (alias) |
| `/study` | `/settings` (hash anchors preserved, e.g. `#settings`) | `StudyRedirect.tsx` |
| `/back-office` | `/settings` | `BackOfficeRedirect.tsx` |
| `/dashboard/settings` | `/settings` | `SettingsPage.tsx` |
| `/claude` | `/settings#agent` | `ClaudeRedirect.tsx` |
| `/onboarding`, `/onboarding/orb` | `/awaken` (the first step of the ritual) | back-compat for inbound email links |

<Note>
The principal's first session is not one of these fourteen — it is the sequential onboarding ritual (`/awaken → /reading-the-room → /verify → /soul → /composing → /preparing → /first-brief → /household → /desk`). See [The onboarding ritual](/surfaces/onboarding-ritual).
</Note>

## How the surface talks to the rest of the stack

Every page reads through Wasp queries that proxy `/api/v1/*` on ctrl-api over the internal Docker network *(packages/web/src/server/tenantProxy.ts:13)*. Authentication is a shared bearer token (`AAS_API_KEY`); the proxy has a 60-second timeout because some vault operations scan thousands of markdown files synchronously *(tenantProxy.ts:16-22)*. The web app itself ships as **two containers** — the Wasp Node server on port 3000 and a static nginx SPA on port 80 — both behind Caddy. UI changes need the `web-client` image redeployed and a hard browser refresh, not just the server.
