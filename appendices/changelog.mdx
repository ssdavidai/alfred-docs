<Update label="2026-05-29 (evening)" description="Tier 4 HA, the alfred-ha Supervisor bridge, Recall replaces Vexa, Tailscale, Files store, Wake words">

A second 2026-05-29 release lands the **household integration wave**:
Home Assistant becomes a first-class principal surface, the meeting bot
moves from self-hosted Vexa to hosted Recall.ai, the VM can now join the
principal's tailnet through a sidecar with an auth-URL flow, the file
store opens as **Store 5**, and HA Voice satellites become reachable —
with the wake-word constraint enumerated for the first time. Eight
feature waves spanning issues #109–#115 + PR #143/PR #161 + the Tier 4
spec lock land here.

**Added — Home Assistant integration (two-way + Supervisor bridge)**

- The 7th `hass` MCP server lands with **26 `ha__*` tools** across three
  tiers: 11 reads (#128), 5 loop-guarded writes (#143), and 10 CRUD
  surfaces for automations / scenes / scripts (#161). Loop-guard
  contract: every write takes a `decision_ref`, ctrl-api persists an
  `ha_run` row BEFORE issuing the upstream call, and `HaWatcherWorkflow`
  suppresses `state_changed` echoes inside a 30 s window so Alfred
  doesn't cycle on his own writes.
- `/channels` Home Assistant card *(packages/web/src/dashboard/HaCard.tsx)*
  — URL + LLAT paste, five states (`unconfigured` / `connecting` /
  `connected` / `error` / `disconnected`), registry summary, Voice
  surface expander. LLAT lives in Vaultwarden, never echoed by the UI,
  redacted to the first 8 chars even in toasts.
- `HaBootstrapWorkflow` Phase A pulls the HA registry on connect + every
  6 h (#147), Phase B+C detect gaps and propose automation packs (#151)
  for principal approval at the Desk.
- `ssdavidai/alfred-ha` HACS integration ships at **v1.1.0** with the
  **Supervisor bridge** — 9 `alfred.supervisor_*` HA services that
  forward to Supervisor REST through HA's auto-injected
  `SUPERVISOR_TOKEN`, giving any LLAT-bearing caller Supervisor scope
  with no SSH or per-addon credentials. Path safety on `/share/*`
  rejects traversal, absolute escapes, symlinks-out, and >10 MB
  payloads.
- Tier 4 spec (`docs/specs/issue-115-ha-tier4-autonomy.md`) locks Sir's
  three defaults: approval gates on irreversible writes, auto-snapshots
  before addon-install / integration-add / core-restart / core-update,
  daybook entries for everything not silently reversible. Eight more
  tools (integrations / HACS / addons / core / backups / users) are
  designed and ship across PR4–PR8.
- See [Home Assistant integration](/integrations/home-assistant) and
  [`hass` MCP reference](/mcp-reference/hass).

**Added — HA Conversation channel (Alfred as HA Assist's brain)**

- `POST /api/v1/channels/ha/turn` route + `channel_tokens` table
  (migration `0004_channel_tokens.sql`, #122). Each typed HA Assist turn
  posts to ctrl-api with `Authorization: Bearer ha_<token>`, validated
  against `channel_tokens.channel='ha-conversation'`, rate-limited 30/min
  per `haInstallId`, forwarded to Hermes-main with session key
  `ha-<haInstallId>` for continuity.
- Channel-token mint/list/revoke/rotate surface (#140) on `/study →
  Channel tokens` — raw token shown exactly once, hashed at rest.
- `HaConversationSetupCard` on `/channels` shows installation status,
  conversation throughput, and a "Mint new token" CTA.
- HA Voice pipeline live wiring + Wyoming fallback (#152, PR5 of #112) —
  voice satellites paired against `voice-bridge`'s ESPHome listener
  (PR2 #132) reach Alfred for both typed and voice turns because HA's
  pipeline picks the conversation agent for both surfaces.

**Added — Wake words + voice satellites**

- `voice-bridge` ESPHome Native API server on `:6053` (#123, #132) —
  the binary HA-internal protocol the satellites speak. Makes

  paths are (a) firmware-flash microWakeWord on the ESP32 directly
  (lowest latency, no public Alfred model exists yet), or (b)
  openWakeWord via the Wyoming addon with the public `alfred.tflite`
  model uploaded into `/share/openwakeword/` (higher latency, runs
  satellite-only-fires-with-Wyoming community firmware). See
  [Wake words](/integrations/home-assistant#wake-words).

<Update label="2026-05-29" description="Paperclip, the codex-builder sandbox, and voice maturity">

Alfred Black gains a **company** around itself, a **sealed engineering
compartment** beneath itself, and a much more honest **voice channel** in
front of itself. The headline integration is **Paperclip** — an
agent-orchestration plane where Alfred is registered as a managed
employee, reachable through a 7th MCP server baked into the Hermes image
and an HMAC-signed inbound heartbeat channel that bridges company tasks
into Hermes-main sessions. The headline architectural addition is
**codex-builder** — a fourth Hermes profile, idle by default, that runs
the OpenAI Codex CLI under uid 10001 inside a three-ring isolation jail
(setpriv + iptables egress + filesystem ACLs). The headline UX win is
the **voice bridge** finally behaving like a butler: realtime turn-detection
swapped to `server_vad`, Twilio playback cleared on barge-in, the
`session.updated` ACK gated before audio flows, and the `self` allowlist
widened to cover the read-only surface voice actually needs.

<Update label="2026-05-25" description="One Alfred — continuity across channels and sessions">

Alfred Black becomes **one Alfred**. Prior to this release, a "delegate" from
the Desk, a Telegram DM, and the morning Brief were three different sessions
in three different worlds — when the principal replied to a reminder, the
agent that received the reply had no memory of having sent it. This release
lands the **One-Alfred continuity layer**: an append-only `alfred_journal` in
`state.db`, a unified outbound endpoint that delivers every Alfred-spoken
message through the same butler-voiced writer, and a Hermes plugin that
injects recent journal entries as authoritative context on the next inbound
turn.

**Added**

- **One-Alfred continuity layer (the centrepiece).** `state.db` gains an
 append-only `alfred_journal` (migration `0002`) plus `alfred_principal` and
 `alfred_principal_channel` tables. Every outbound Alfred message and every
 inbound principal turn becomes a journal row keyed by
 `principal_id × channel × chat_id` with stable `(ts, rowid)` ordering.
- `POST /api/v1/alfred-deliver` — the **single butler-voiced outbound**.
 Used by `notify_principal`, by the delegate handoff, and by the Desk
 "Hand it to Alfred" action. Talks directly to `api.telegram.org` and
 `slack.com/api/chat.postMessage`; no Hermes webhook roundtrip.
- `packages/hermes/plugins/one-alfred/` — a Hermes plugin with three hooks
 (`pre_gateway_dispatch`, `pre_llm_call`, `post_llm_call`) that injects
 recent journal entries as **authoritative** continuity (`[ALFRED-CONTINUITY
 — authoritative]` + "these DID happen"). 5-second dedupe latch.
- **Channels — Telegram and Slack go live** at `/channels`. Manifest-paste /
 token-paste setup, paired-chat management, send-test, disconnect, runtime
 workspace info, all backed by `/api/v1/channels/{telegram,slack}/*` routes
 on ctrl-api that write directly to the per-profile Hermes `.env`.
- **Agent-autonomy toggles** at `/settings#agent`: `signal_action_mode`,
 `state_mutator_mode`, `auto_task_create_mode` (`live | shadow | off`,
 default `live`). See [Mode flags](/troubleshooting/gotchas#mode-flags--defaults).
- **Delegate pipeline end-to-end**: `DecisionRouter` fires
 `dispatch_action_to_agent` for `intent=delegate`; the dispatch path mints a
 re-routed signal in terminal state so `SignalRouter` cannot loop on its own
 output; `principal_note` is the canonical task (`action_what` demoted to
 context); `route_decision` budget grows from 60s to 1000s with a
 `recover_stuck_dispatching` safety net.

**Changed**

- Instinct scorer matches **multi-word patterns**; `MATCH_THRESHOLD` drops
 from 0.15 → 0.10 → 0.05 across two rounds. The matcher reliably finds
 matches. See [Incident history](/troubleshooting/incident-history).
- Unconfirmed instincts are included in the matcher load.
- The signal→instinct loop persists `matched_instinct` end-to-end.
- Chore-run observations now route to `state.db` (not the vault).
- `/api/v1/notifications` is a thin forwarder to `/api/v1/alfred-deliver`.
- `DISPATCH_USE_EPHEMERAL_EXECUTOR=1` is the default in `docker-compose.yaml`.

**Fixed**

- `/channels` Telegram card: the broken `POST /pair` (which called a
 non-existent `hermes pairing mint` subcommand) is dropped; the card now
 reads the real `paired_chats` list.
- `alfred-deliver` no longer routes through a Hermes webhook subscription —
 it delivers bytes directly and journals the result.
- `one-alfred` plugin: `post_llm_call` now accepts both `assistant_response`
 (Hermes' real kwarg) and `response_text`; the continuity framing is
 authoritative, not advisory; the re-injection latch drops from 10 minutes
 to 5 seconds.
- Telegram bot-token regex relaxed (`{30,}` rather than `{35}` exact);
 modern tokens stopped 400-ing at the gate.
- Init `.env` renderer preserves `TELEGRAM_*`, `SLACK_*`, `DISCORD_BOT_*`,
 `WHATSAPP_*`, `SIGNAL_*`, `MATRIX_*`, `MATTERMOST_*`, `BLUEBUBBLES_*`
 across re-renders.
- Fresh-deploy correctness: `matter/inbox.md` seeded on first boot;
 `_resolve_parent_matter_path` validates with 4-tier fuzzy fallback;
 onboarding writes tasks in their rich shape with `parent_matter` linkage;
 task status vocab harmonised to the validator (`'queued' → 'todo'`).

**Migration**

- `state.db` migration `0002_alfred_journal.sql` runs transactionally on
 ctrl-api boot. Additive (three tables + indexes); no data migration.
- The `one-alfred` Hermes plugin is enabled on the `main` profile only.
- Set `DISPATCH_USE_EPHEMERAL_EXECUTOR=0` to revert to the legacy dispatch
 path.

</Update>

<Update label="2026-05-24" description="Promotion contract, personalised SOUL, junk suppression">

Alfred Black goes from "a Hermes runtime with tools" to "an agent with a
persistent operational understanding of the principal." The runtime now boots
with the principal's soul, standing rules, and a curated working memory in
every system prompt; the vault populates with substantive matters, people,
orgs, chores, and instincts grounded in the principal's actual email history;
and the LCM cross-session memory plugin is baked into the main Hermes
profile so context survives across sessions.

The single biggest architectural shift is a **promotion contract** between
the writers (the learn pipeline) and the vault gate (ctrl-api). Junk
suppression — fabricated instinct confidence, per-service-sender notes,
domain-only "orgs", non-human "persons", matter-per-domain explosion — is
enforced both at the writer and re-enforced at the gate,
so a bug on one side cannot pollute the principal's surface. The result is a
first Brief composed against thousands of real emails, a vault the principal
can actually read, and a Desk that has cards on day one.

This is also the first release shipped under the current fix-campaign
protocol: ~85 findings landed as gate-protected, contract-frozen lane
fan-outs with a golden-fixture
quality test suite guarding regressions. See [Bug-fixing protocol](/contributing/bug-fixing-protocol).

**Hermes runtime additions**

- `hermes-lcm` cross-session memory plugin installed and pinned for the
 `main` profile, with runtime verification at supervisor boot.
- `MEMORY.md` and `USER.md` seeded into `$HERMES_HOME/memories` at
 onboarding time.
- Consolidated personalised `SOUL.md` deployed into each Hermes profile and
 re-consolidated at supervisor boot.
- `main` is the sticky default profile; each gateway launches with its
 profile directory as CWD so `AGENTS.md` loads as designed.

**Onboarding artefacts**

- `vault/SOUL.md` written once during onboarding.
- `vault/RULES.md` — principal-facing standing-rules document, surfaced in
 the web UI.
- Day-one Desk seeds via `seed_day_one_desk_cards` so `/desk` isn't empty on
 first login.

**Web UI**

- `/household` ships a structured `RULES.md` editor.
- Matter relationship graph on matter detail, with CRM-style key-people /
 orgs links.
- Decision cards expose `signal → matter/task` provenance.
- `/connections` app launcher with multi-field API-key credential UI.
- Hermes auth-unhealthy banner with re-auth CTA on `/connections`.
- Approval-secret rotation with a reveal-once panel.

**Promotion contract enforcement**

- Junk-suppression filters at materialise time: non-human "persons" rejected
; orgs restricted to facts-grounded names; the heuristic
 matter_pack fallback that wrote fragment matters is gone;
 per-service-sender summary notes suppressed at curator S1.
- The C-OB1 gate at vault `POST` (ctrl-api) re-enforces the same contract.
- Matter-pack near-duplicate dedup using token-set overlap ≥ 0.7.
- Instinct tier and discretion clamped to the observation-earned ceiling —
 fabricated "high-confidence" instincts no longer ship (C-B6, B6, C-OB4).
- Orgs deterministically materialised from extracted facts (no LLM, no
 timeout).

**Signal → decision pipeline**

- Token/entity signal→target matcher prefers `None` over a wrong bind (P0-1).
- Relevance + dedup gate before any signal becomes a Desk card (P0-2).
- Brief's propose-clerk fed signal/decision **content**, not just identifiers

<Update label="2026-05-20" description="The Alfred Black platform — first release">

The first release of the Alfred Black platform: a complete, deployable
agentic butler with a real UI, onboarding, a daily Brief, and a one-command
self-hosted deploy.

**The platform**

- **One-VM `docker compose up`** deploy. Bring a fresh Linux VM and a
 domain; the stack brings everything else and serves the web app over
 HTTPS.
- **Web dashboard** for working with the vault.
- **Hermes runtime** — a single isolated container that supervises three
 profiles (`main`, `workers`, `heavy`).
- **Bundled Caddy** reverse proxy with automatic per-host TLS (Let's
 Encrypt HTTP-01); no DNS API token required.
- **Four-store storage model**: the vault (markdown), `alfred-state.db`
 (working memory), `cold.db` (forensic long-tail >90 days), and `ingest.db`
 (raw inbound stream, 7-day TTL).
- **Sidecars**: Plane (project management), Sure (personal finance),
 Vaultwarden (secrets manager).
- **Optional Vexa profile** for meeting transcription, off by default
 (`docker compose --profile vexa up -d`).

**Onboarding + Brief**

- Automatic owner onboarding ritual: connect Gmail, backfill recent email,
 build a behavioural profile, confirm the inferred facts.
- Daily Brief surface composed for the owner.

**alfred-vault 1.0.0**

The pip-installable CLI lives in this monorepo at `packages/alfred-vault/`.
The platform's vault daemon runs the same engine.

**Versioning**

The `alfred-vault` package and the platform version independently. The
package uses SemVer and publishes to PyPI on `alfred-vault-vX.Y.Z` tags; the
platform uses date-based releases.

</Update>
