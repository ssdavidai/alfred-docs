Alfred Black is configured by a single `.env` file at the repo root. The template at `.env.example` *(`.env.example:1-207`)* is the source of truth; this page documents every variable it ships with.

There are three classes of variable:

- **Required** — `scripts/bootstrap.sh` refuses to run until these are set *(`scripts/bootstrap.sh:71-99`)*.
- **Optional** — disabled or fall back to defaults if left blank.
- **Auto-generated** — `bootstrap.sh` appends each via `openssl rand -hex 32` if missing *(`scripts/bootstrap.sh:115-172`)*. Never fill these by hand.

<Warning>
Run `./scripts/bootstrap.sh` **once**, after filling the Required block, and **before** `docker compose up -d`. It is idempotent — re-running never overwrites an existing non-empty value *(`scripts/bootstrap.sh:147-154`)* — so it is safe to re-run any time you add a new required field.
</Warning>

## Required

`bootstrap.sh` exits 1 if any of these are empty or whitespace-only *(`scripts/bootstrap.sh:71-98`)*. The trim self-check at startup rejects values that look set but are blank *(`scripts/bootstrap.sh:65-68`)*.

| Variable | Purpose | Consumed by |
|----------|---------|-------------|
| `DOMAIN` | Apex domain the stack is served on (e.g. `home.example.com`). All sidecars live at subdomains of this name — the dashboard at `https://${DOMAIN}`, the API at `api.${DOMAIN}`, etc. Point seven A-records at the VM before `docker compose up` *(`.env.example:14-17`, `caddy/Caddyfile:34-121`)*. | `caddy`, `web`, `web-client`, `ctrl-api`, `mcp-server`, `sure-web`, `plane-api`, `vaultwarden`, `vexa-dashboard` |
| `ACME_EMAIL` | Contact address for Let's Encrypt cert registration. Caddy uses HTTP-01 to issue one cert per host *(`caddy/Caddyfile:17-19`)*. | `caddy` |
| `OWNER_NAME` | The principal's display name. Shown across the dashboard, embedded in the MCP server's tenant label *(`.env.example:22-23`)*. | `init`, `mcp-server` |
| `OPENROUTER_API_KEY` | API key for OpenRouter. Default model routing for all three Hermes profiles goes through OpenRouter *(`packages/hermes/render_hermes.py:338-340`)*. | `hermes`, `alfred-learn` |
| `COMPOSIO_API_KEY` | Composio is the third-party tool/integration broker (Gmail, Calendar, 1000+ apps). The onboarding "connect Gmail" flow uses Composio's managed OAuth *(`.env.example:31-32`, `.env.example:46-49`)*. | `init`, `ctrl-api`, `alfred-learn` |

<Note>
`ANTHROPIC_API_KEY` is **not** required — bootstrap explicitly tolerates it being blank *(`scripts/bootstrap.sh:78-79`)*. Set it only if you want a direct Anthropic route instead of routing Claude traffic through OpenRouter.
</Note>

## Optional — features and integrations

| Variable | Purpose | Default |
|----------|---------|---------|
| `SURE_ENABLED` | Run the Sure personal-finance sidecar | `true` *(`.env.example:72-75`)* |
| `VEXA_ENABLED` | Run the Vexa meeting-transcription stack (9 extra containers, profile `vexa`) | `false` *(`.env.example:77-79`)* |
| `VEXA_TRANSCRIPTION_URL` | Whisper endpoint for Vexa | `https://api.groq.com/openai/v1/audio/transcriptions` *(`.env.example:113`)* |
| `VEXA_TRANSCRIPTION_TOKEN` | Bearer for the above | Required when `VEXA_ENABLED=true` |
| `GROQ_API_KEY` | OMI ambient-wearable transcription via Groq Whisper | Distinct from `VEXA_TRANSCRIPTION_TOKEN` — without it every OMI audio group is discarded as empty *(`.env.example:116-121`)*. |
| `STEWARD_SIGNAL_EXTRACT_ENABLED` | Registration-time gate for `SignalExtractWorkflow` (signal pipeline stage 1) | `true` *(`.env.example:128`, `packages/learn/src/workflows/signals.py`)* |
| `STEWARD_SIGNAL_ROUTER_ENABLED` | Registration-time gate for `SignalRouterWorkflow` (signal pipeline stage 2) | `true` *(`.env.example:129`)* |

The two `STEWARD_*` flags above gate **schedule registration** at worker boot. Toggling them post-boot has no effect — the workflows must be re-registered. For the runtime mode flags (`signal_action_mode`, `state_mutator_mode`, `auto_task_create_mode`) see [the mode flags page](/configuration/mode-flags).

## Auto-generated by bootstrap

`scripts/bootstrap.sh` runs `openssl rand -hex 32` for each of the entries below and appends or in-place-replaces the variable in `.env` *(`scripts/bootstrap.sh:115-172`)*. Re-running the script after a fresh `.env.example` copy is the supported way to top up missing secrets.

| Variable | Format | Consumed by |
|----------|--------|-------------|
| `COMPOSIO_USER_ID` | `alfred-owner-<4-byte-hex>` (readable, not 32-byte hex) *(`scripts/bootstrap.sh:174-193`)* | `init`, `ctrl-api` (rejects empty or literal `"default"`) |
| `AAS_API_KEY` | 64-char hex | `web`, `ctrl-api`, `mcp-server` (shared bearer for web → ctrl-api → MCP) |
| `COLUMN_ENCRYPTION_KEY` | 64-char hex (AES-256-GCM key) | `web` — encrypts OAuth credential tokens at rest |
| `JWT_SECRET` | 64-char hex | `web` — Wasp session JWT signing |
| `HERMES_API_SERVER_KEY` | 64-char hex | `hermes`, `alfred-learn`, `init` — the gateway bearer token, written to `/alfred-data/.gateway-token` and stamped into each Hermes profile's `.env` as `API_SERVER_KEY` *(`packages/hermes/init/entrypoint.sh:327-352`)* |
| `WEB_DATABASE_PASSWORD` | 64-char hex | `web`, `web-db` (Postgres for Wasp) |
| `VAULTWARDEN_ADMIN_TOKEN` | 64-char hex | `vaultwarden`, `vault-signup`, `vault-cli` (`/admin` access) |
| `VAULTWARDEN_BW_PASSWORD` | 64-char hex | `vault-signup`, `vault-cli` (the principal's auto-created Bitwarden account password) |
| `MCP_APPROVAL_SECRET` | 64-char hex | `mcp-server`, `voice-bridge` — signs tool-approval requests |
| `DJANGO_SECRET_KEY` | 64-char hex | `plane-api`, `plane-worker`, `plane-beat`, `plane-migrator`, `plane-init` |
| `POSTGRES_PASSWORD` | 64-char hex | `plane-db` + every Plane container that talks to it |
| `REDIS_PASSWORD` | 64-char hex | `plane-redis` + every Plane container that uses Valkey |
| `MINIO_ROOT_PASSWORD` | 64-char hex | `plane-minio` + Plane services that read uploads |
| `LIVE_SERVER_SECRET_KEY` | 64-char hex | `plane-live` (WebSocket live-collaboration server) |
| `SURE_SECRET_KEY_BASE` | 64-char hex | Rails secret for `sure-web`, `sure-worker`, `sure-init` |
| `SURE_POSTGRES_PASSWORD` | 64-char hex | `sure-db` + Sure containers |
| `SURE_REDIS_PASSWORD` | 64-char hex | `sure-redis` + Sure containers |
| `SURE_API_KEY` | 64-char hex (matches Sure's `SecureRandom.hex(32)` shape) | `sure-init` seeds it into Sure's DB; `ctrl-api` reads it for the REST proxy *(`.env.example:195-198`)* |
| `VEXA_POSTGRES_PASSWORD` | 64-char hex | Vexa Postgres + clients (profile `vexa`) |
| `VEXA_MINIO_PASSWORD` | 64-char hex | Vexa MinIO + clients |
| `VEXA_ADMIN_API_TOKEN` | 64-char hex | `vexa-admin-api`, `vexa-dashboard` |
| `VEXA_INTERNAL_API_SECRET` | 64-char hex | `vexa-admin-api`, `vexa-runtime-api`, `vexa-meeting-api`, `vexa-api-gateway` |

The Vexa secrets are generated unconditionally even if `VEXA_ENABLED=false`, so flipping the profile on later works without re-running bootstrap.

## Variables you should not normally set

The compose file also reads a handful of variables that have working defaults baked into the services and are documented here only for completeness — change them only if you understand the consequences.

| Variable | Default | Why you might change it |
|----------|---------|------------------------|
| `HERMES_CRON_TIMEOUT` | `1800` (seconds) *(`docker-compose.yaml:288`)* | Hermes cron-task timeout. Raise for long-running chores. |
| `NODE_OPTIONS` (Hermes) | `--max-old-space-size=3072` *(`docker-compose.yaml:275`)* | V8 heap cap for the runtime. Don't shrink. |
| `MAX_CALL_SECONDS` (voice-bridge) | `1800` *(`docker-compose.yaml:607`)* | Max length of a single Twilio voice call. |
| `IDLE_HANGUP_SECONDS` (voice-bridge) | `60` *(`docker-compose.yaml:608`)* | Auto-hangup on silence. |
| `VOICE_ALLOW_ALL_CALLERS` | unset (allowlist enforced) *(`docker-compose.yaml:599`)* | Set to `true` to skip the `VOICE_ALLOWED_CALLERS` check — only for debug. |

## How variables flow through compose

The compose file *(`docker-compose.yaml:1-1514`)* pulls values from `.env` via the standard `${VAR}` syntax and mirrors many of them onto multiple services. For example, `DOMAIN` is referenced by 9 services so that each can build its own public URL; `HERMES_API_SERVER_KEY` becomes `OPENCLAW_GATEWAY_TOKEN`-equivalent on services that talk to Hermes; `OWNER_EMAIL` is also mirrored into `ALFRED_OWNER_EMAIL` because legacy transcript code still reads the older name *(`.env.example:81-87`)*.

If you change a `.env` value after the stack is up, you must `docker compose up -d` (without `--force-recreate` unless you've hot-patched something — see [redeploying](/operations/redeploy)) to propagate the new value into the affected containers.
