## Overview

Returns the per-MCP-server disposition map that controls whether each server's tools are exposed inline on the main Hermes profile (**DIRECT**) or hidden behind the `delegate_to_focused_agent` gateway (**DELEGATED**). Backed by `state.db.tool_disposition` (migration `0014`) *(packages/ctrl/src/api/routes/agents.ts)*.

The disposition table seeds every server as `direct` at first boot — initial deploy is behaviour-identical to pre-Phase-B. Sir flips servers to `delegated` (via the `/tools` UI or `set_tool_disposition` MCP tool) when he wants the token savings on a server he uses infrequently, accepting the +3–5 s delegation hop per tool use.

The dashboard polls this route to render the `/tools` MCP-servers section; Alfred's `list_tool_dispositions` MCP tool exposes the same map so a fresh session can glance the current state before deciding whether to call a native tool or delegate.

## The 9 known servers

```
alfred-ctrl    alfred    sure       plane      vaultwarden
execute        paperclip hass       files
```

Anything outside this allowlist is rejected by the [POST endpoint](/api-reference/agents/set-tool-disposition). New servers must be added by migration before they can be flipped.

## Response

<ResponseField name="dispositions" type="array">
 One row per known server, ordered alphabetically by `server`.

 <Expandable title="Disposition fields">
 <ResponseField name="server" type="string">
 MCP server name (one of the 9 known servers).
 </ResponseField>
 <ResponseField name="disposition" type="string">
 Current state — `direct` or `delegated`.
 </ResponseField>
 <ResponseField name="updated_at" type="string">
 ISO-8601 UTC timestamp of the most recent write.
 </ResponseField>
 <ResponseField name="updated_by" type="string">
 Who wrote the row — `init` (migration seed), `sir` (dashboard flip), or `alfred` (`set_tool_disposition` MCP tool).
 </ResponseField>
 </Expandable>
</ResponseField>
