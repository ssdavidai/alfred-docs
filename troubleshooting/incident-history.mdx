This page is the incident log — kept here so the *why* behind quirky code is
never lost. Each entry is a one-liner symptom, the actual root cause, and the

## 2026-05-24 — the Desk loop closure campaign

A single day produced ~85 findings and twelve fixes across all five lanes. The
common thread: the signal-to-instinct-to-decision learning loop was broken in
several silent ways, so the system **looked** healthy from the outside while
no observations were landing in `state.db` and no instincts were promoting.

| Symptom | Root cause | Fix |
|---|---|---|
| Onboarding wrote degenerate task shape (no `parent_matter`, no `state`, no `closure_predicate`); 32 tasks orphaned from matters | The `packs_opus` errand-pack writer wasn't using the rich shape; `_resolve_parent_matter_path` blindly slugified the LLM's `related_matter` string | `dbaca81` (in the `learn` package): rich shape + 4-tier resolver + `state_mutator_mode` defaults to `live` + `auto_task_create_mode` defaults to `live` |
| Task `status: queued` rejected by alfred-vault validator → backfill 100% errored | `tasks.py:23` had an aspirational `'queued'` value in a comment that became canon in newer writers; the daemon validator's vocabulary is `active \| blocked \| cancelled \| done \| todo` | `eed3799` (orchestrator) — harmonise to `status: todo` end-to-end, plus tests in `e3c1ad2` updated in the same PR |
| `DecisionRouter` delegate path minted a fresh mirror `decision/<ts>.md` every cycle → the agent fired every minute forever | `attention.ts.mintDecisionMirror` had no recursion guard; the router's own dispatch hit `/dispatch` which minted another decision which the router then processed | `4466c68` (orchestrator) — `/dispatch` skips `mintDecisionMirror` when `decision_origin` is set in the body |
| Delegate clicks never fired the agent | A prior change in the `ctrl` package had severed `signal-router`'s `principal_delegate_override` path; nothing else dispatched | `6a8052f` (in the `learn` package) — `DecisionRouter` calls `dispatch_action_to_agent` directly when intent is delegate |
| One delegate click produced ten dispatches | The delegate dispatch minted a `status=unrouted` signal, which `SignalRouter` re-dispatched on every 2-minute tick | `c551c00` (in the `ctrl` package) — mint the re-routed signal in terminal state (`routed_agent`) so `SignalRouter` cannot loop on its own output |
| `POST /api/v1/decisions` minted done/noise/take-mine in `state=completed` → `DecisionRouter` skipped → 0 `kind=decision` observations | The Desk write path was minting decisions in their final state, so the router's `extract_observation_from_decision` never ran | `31fa11f` (orchestrator) — always mint `state=open`; `e8905e4` does the same for the legacy attention mirror |
| Instinct scorer returned 0.0 for every signal | `_score_keyword_overlap` did set intersection of single-word tokens against multi-word patterns; structurally impossible to match | `c27e6e3` (in the `learn` package) — three-matcher fix at `MATCH_THRESHOLD = 0.05` |
| Instinct matcher loaded nothing | `_load_active_instincts` filtered on `status=active`, but unconfirmed instincts have `status=unconfirmed` | `c27e6e3` (in the `learn` package) — accept all non-deprecated instincts; the discretion gate is the real safety belt |
| `chore-run` observations were landing in the vault instead of `state.db` | The chore-run seed routed to the wrong store | `de34f6d` (in the `web` package) |
| Several principal-listed UX bugs (brief shape, /desk duplicates, /chores truncate, /connections icons, /channels Terminal card, /plane blank, Vault→Vaultwarden rename, ssh-info endpoint) | Multiple — cross-cutting | `ctrl` / `learn` / `web` / `edges` packages — four PRs, 1,978 LOC, 30 new tests |
| `home.alfred.black` swap from `test.alfred.black` | Apex domain change | One `.env` flip; Caddy auto-reissued six Let's Encrypt certs |

The campaign's lesson: **the loop closes at `extract_observation_from_decision`**.
If observations aren't landing in `state.db` for every Desk click, the system
isn't learning, no matter how good the rest of the pipeline looks.

## 2026-05-24 — the Hermes web dashboard non-fix

Hooking up `hermes.{$DOMAIN}` to the upstream Hermes dashboard backend looked
straightforward — the gateway image already runs the dashboard server on its
configured port. After deploying, the route worked but every page returned
`{"error":"Frontend not built"}`.

<Note>
**Root cause**: the `hermes-agent` v0.14.0 pip wheel ships neither the React
source code nor a built `web_dist/`. The backend always 500s the frontend.
**Fix**: revert (`ce6c177`). Use `docker compose exec hermes hermes …` CLI
instead. See [Gotchas → The Hermes web dashboard](/troubleshooting/gotchas#the-hermes-web-dashboard-is-not-usable).
</Note>

## 2026-05-23 — sentence-boundary truncation

The onboarding `personalize_opus` activity writes `USER.md` from the LLM's
behavioural profile output, capped at ~1375 characters. The naive
truncator did `text.rfind('.', 0, cap)` — but on a long paragraph with the
last sentence break near position 53 of a 1407-char document, the cap landed
at 53 characters and threw away 96% of the content.

<Note>
**Fix**: sentence-boundary truncation with a floor fraction — accept the last
sentence break only if it sits within `[0.85 * cap, cap]`; otherwise truncate
at the cap and append an ellipsis. Same fix in `MEMORY.md`.
</Note>

## 2026-05-23 — hermes-lcm plugin baked but not loaded

The cross-session memory plugin (`hermes-lcm`) was baked into the Hermes image
at `/opt/hermes-lcm/` but the install step into the `main` profile's `plugins/`
dir wasn't running, so the plugin was on disk and never imported.

<Note>
**Fix**: `verify_lcm()` background probe in the Hermes supervisor that asserts
the plugin loaded at boot, plus a per-profile plugin directory copy so the
install is idempotent across restarts. Failure now surfaces in `docker compose logs hermes`.
</Note>

## 2026-05-22 — the 0522 fix-fan-out campaign

A 21-finding sweep over the live product produced eight image deploys and
twenty-one fixes shipped as PRs. This is the campaign that produced the
current lane protocol: gate-protected fix fan-out, contract freezes
(`C12–C19`), failing-test-first discipline. See [Contributing →
Bug-fixing protocol](/contributing/bug-fixing-protocol) for the rules.

Notable individual fixes:

- **Composio bulk pull >4MB**. `composio_pull` was returning a
  >4MB payload to the Temporal activity, blowing past the gRPC limit. Fix:
  self-ingest oversized batches with chunked pagination.
- **Chore cron-DOW mismatch**. Generated chores were stuck in a
  validator loop because the cron string used `Mon-Fri` instead of `1-5`. Fix:
  `_autocorrect_cron_dow_for_description` rewrites before validation.
- **Onboarding context overflow**. `extract_facts_opus` was passing
  the entire backfill (~2000 messages) to the LLM in one prompt, hitting
  Hermes' max-compression-attempts ceiling. Fix: chunked extraction
  (chunk_threshold=500, chunk_size=400).
- **Empty Desk on day one**. New tenants landed on `/desk` with
  zero cards. Fix: `seed_day_one_desk_cards` picks time-anchored matters
  during onboarding so the first impression isn't empty.
- **Delegate signal loops**. Documented above (2026-05-24); root
  cause traces back here.
- **Duplicate decision on dispatch**. The orchestrator suppresses
  the decision mirror when the call originates from the router.
- **Matters list vs detail tasks count diverge**. The list endpoint
  counted tasks by one query, the detail endpoint by another. Fix: consolidate
  on a single canonical query.

## Recurring failure classes (audit, 2026-05-20)

The `docs/FAILURE-MODES.md` audit identified six systemic classes that account
for nearly every failure observed in production:

1. **Silent under-extraction** — gpt-4.1-nano misses signals; no error, no
   card, no surface. The class with the worst trust impact.
2. **Autonomous wrong action** — a generated chore or instinct misfires
   repeatedly, unattended.
3. **Promotion-contract gaps** — writers `422` silently after a store change,
   losing audit/state without surfacing.
4. **Temporal stalls** — zombie or replay-failure workflows freeze autonomy
   while the UI stays green.
5. **Resource exhaustion** — 32 GB single-VM has no HA; one pressure point
   drops the whole butler.
6. **Cost blowup** — Opus everywhere + per-email extraction can bill quietly
   high.

<Tip>
**Meta-finding**: nearly every failure is silent. The highest-leverage fix is
to make failure loud — health probes proving the signal pipeline ran, the
steward swept, chores fired, extraction isn't zeroing, the bill is sane
*(docs/FAILURE-MODES.md "Meta-finding")*.
</Tip>
