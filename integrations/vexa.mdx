[Vexa](https://github.com/Vexa-ai/vexa) is the meeting-transcription stack Alfred ships as an **opt-in** sidecar. It does not run by default. Enable it only if you actually want Alfred to join your meetings, record them, and turn the transcripts into signals for the Desk and the brief.

## Why opt-in

Vexa is heavy. The full stack adds nine containers, roughly **7 GB of additional RAM**, persistent recording storage in MinIO, and an upstream transcription dependency (Groq Whisper by default). On a 48 GB VM — the recommended Alfred floor — that takes you from ~37 GB used to ~44 GB used *(R7-infra.md §1, default profile ~37 GB ceiling)*. Below 56 GB total RAM you'll feel the squeeze under load.

If you don't have meeting flows that justify the cost (running team standups, sales calls, therapy sessions, podcast recording), leave it off.

## What it contains

All nine services carry `profiles: ["vexa"]` *(docker-compose.yaml:1251–1489)*:

| Service | Image | Purpose |
|---|---|---|
| `vexa-redis` | `redis:7-alpine` | Cache + queue |
| `vexa-postgres` | `postgres:17-alpine` | Primary database |
| `vexa-minio` | `minio/minio:latest` | S3-compatible recording storage |
| `vexa-minio-init` | `minio/mc:latest` | One-shot bucket setup |
| `vexa-admin-api` | `vexaai/admin-api:0.10.6` | Admin backend |
| `vexa-runtime-api` | `vexaai/runtime-api:0.10.6` | Spawns Vexa-bot containers per meeting |
| `vexa-meeting-api` | `ssdavidai00/vexa-meeting-api:latest` | Records, ingests transcripts |
| `vexa-api-gateway` | `vexaai/api-gateway:0.10.6` | Entry point for all Vexa HTTP traffic |
| `vexa-dashboard` | `ssdavidai00/vexa-dashboard:latest` | Web UI on `:3000` |

`vexa-runtime-api` mounts the host docker socket so it can spawn `vexaai/vexa-bot:0.10.6` containers as siblings, one per active meeting *(docker-compose.yaml:1376)*. That's how the bot actually joins a Google Meet / Zoom / Teams call — as a transient browser container.

## Turning it on

<Steps>
  <Step title="Set the env flag">
    Edit `.env`:
    ```sh
    VEXA_ENABLED=true
    VEXA_TRANSCRIPTION_URL=https://api.groq.com/openai/v1/audio/transcriptions
    VEXA_TRANSCRIPTION_TOKEN=<your-groq-key>
    ```
    The four Vexa-specific secrets (`VEXA_POSTGRES_PASSWORD`, `VEXA_MINIO_PASSWORD`, `VEXA_ADMIN_API_TOKEN`, `VEXA_INTERNAL_API_SECRET`) are already generated by `bootstrap.sh` *(scripts/bootstrap.sh:115–172)*.
  </Step>
  <Step title="Re-run bootstrap (optional)">
    `./scripts/bootstrap.sh` is idempotent. Run it again if you didn't have the Vexa block in `.env` originally.
  </Step>
  <Step title="Bring up the profile">
    ```sh
    docker compose --profile vexa up -d
    ```
    The first start takes longer than usual — `vexa-postgres` runs migrations, `vexa-minio-init` provisions the bucket, the bot image gets pulled.
  </Step>
  <Step title="Sign in">
    The Vexa dashboard lives at `https://vexa.{$DOMAIN}` after you add a Caddy site block (Vexa is not in the default Caddyfile — point it at `vexa-api-gateway:8000` or `vexa-dashboard:3000` depending on which UI you want).
  </Step>
</Steps>

## How Alfred uses it

Once the profile is up, `alfred-learn` reads `VEXA_ENABLED` and `VEXA_API_URL` *(docker-compose.yaml:513–515)*; the workflow that watches your Calendar starts dispatching the Vexa bot to scheduled meetings the principal accepts (matched by `OWNER_EMAIL` against the attendee list). The bot joins, records audio, streams it to `vexa-meeting-api`, which forwards to the transcription service in chunks.

Completed transcripts land back in `ingest.db.stream_event` as a new event type. The signal pipeline extracts signals from them — action items, follow-ups, dates mentioned — exactly the same way it handles Gmail and Calendar signals. From the principal's point of view, meeting transcripts become Desk cards and matter notes without any extra wiring.

The Vexa dashboard at `vexa.{$DOMAIN}` also points at Hermes for AI-assisted summarisation *(docker-compose.yaml:1473–1474)* — `AI_BASE_URL=http://hermes:18789/v1`, `AI_MODEL=openai/hermes/main`. The same Hermes runtime serves both the chat surface and Vexa's transcript summaries.

## Costs

Self-hosted Vexa runs free of upstream charges for the containers themselves; the transcription provider is the cost line. Groq Whisper (the default) is cheap by current standards — roughly $0.04 per hour of audio at the time of writing. A 30-minute meeting is a couple of pennies; a daylong all-hands is under a dollar. Other transcription providers (OpenAI Whisper, AssemblyAI) are substitutable via `VEXA_TRANSCRIPTION_URL` if you'd rather not depend on Groq.

<Warning>
The `vexa-runtime-api` container mounts the host docker socket *(docker-compose.yaml:1376)* and runs without `cap_drop: ALL` because the upstream image hasn't been audited for cap drops. This is a higher-privilege footprint than the rest of the stack. Treat the Vexa profile as a deliberate trust decision; isolate it on a separate VM if you handle sensitive meeting content.
</Warning>
