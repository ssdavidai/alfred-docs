Alfred Black is an **open-source AI butler that runs entirely on one Linux VM**. You clone a repo, fill in a `.env`, run a bootstrap script, and `docker compose up -d`. There is no SaaS account to create, no managed provisioner to talk to, no overlay network to join, no billing wall. The whole household runtime — dashboard, intelligence layer, sidecars, TLS, ingress — comes up on your own machine, against your own domain.

Alfred Black is **one repo, one VM, one stack** *(CLAUDE.md §1)*.

## The principal model

Alfred treats the person it serves as a **principal**, not a "user". The principal has a household — matters they care about, people they answer to, chores that recur, decisions that need making — and Alfred's job is to keep that household functioning without becoming yet another inbox. See [The principal model](/introduction/the-principal-model) for the framing in full.

## The five-store architecture

The vault is **the principal's published surface, not the system's database**. Behind it, five physical stores split responsibility *(packages/ctrl/docs/STORAGE-ARCHITECTURE.md)*:

| # | Store | Backing | Purpose |
|---|-------|---------|---------|
| 1 | **Vault** | Markdown files in `vault_data` | Twelve canonical record types the principal reads and edits in Obsidian |
| 2 | **`alfred-state.db`** | SQLite + WAL + sqlite-vec | Machine working memory — signals, observations, audit, embeddings |
| 3 | **`ingest.db`** | SQLite | Raw inbound stream events (7-day TTL) |
| 4 | **Cold archive** | SQLite + zstd-compressed blobs | Forensic long tail (>90d for signals/observations) |
| 5 | **Files** | `files_data` + `files_cold_data` volumes; metadata in `alfred-state.db.files` | Binary blobs the principal owns and Alfred can read — PDFs, audio, archives |

`ctrl-api` is the **sole writer** of stores 2–5. Everything else — `alfred-learn`, the vault daemon, the MCP servers — writes through HTTP endpoints. This eliminates multi-process SQLite contention and makes vault drift structurally impossible *(CLAUDE.md §5.2)*.

## The licence and the posture

Alfred Black is MIT-licensed and built to be forked. The code, the contracts, the bootstrap script, the Caddyfile, the compose graph — everything you need to stand up your own instance — is in one repo. There is no telemetry. There is no managed offering. Your data lives in Docker volumes on your VM; back them up like you would any other database.

What you give up by choosing the single-VM build is HA, horizontal scale, and the hand-holding of a hosted product. What you get is a butler whose every decision you can audit, whose every secret you hold, and whose every container you can stop.
